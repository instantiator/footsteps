## Context

In `mouse-feet` mode the pointer is player 1's feet (`MouseFeet`, `src/components/core/layout/MouseFeetHook.ts`), but
nothing is drawn for them, and they are a single point, so a rule's `threshold` does nothing. It is the fallback for
the demo's floor stages, so it's how most people try them without a camera.

### Decisions taken

| Decision              | Choice                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Setting               | `avatar.feet` (`GameSceneAvatarFeetData`), beside `mode`, `fallback` and `preview`, on `modules.avatar`, every scene and reset scene. It is read only while the resolved mode is `mouse-feet`, including as a camera fallback.                                                                                                                                                                                                 |
| Inheritance           | Key by key, most specific first: the first active challenge with a `feet` setting, over the stage scene's, the overview scene's and the game's, as `resolveSpectators` does. `avatarOver` (for reset scenes) merges `feet` key by key too, and keeps the broader `feet` when the narrower setting changes `mode`, as it keeps `preview`.                                                                                       |
| Look (user)           | `size` (the footprint's diameter in floor units; default 6), `color` (CSS; default a translucent white with a dark rim), and `imageResource` (a resource drawn upright, standing on the feet, instead of the circle). The element has the `mouse-feet-avatar` class, and `data-airborne` mid-jump, so a game's stylesheets can restyle it. No HTML template.                                                                   |
| Shape (user)          | In a 2.5D scene the avatar is a floor item in the depth stack: `data-floor-x`, `data-floor-y` and `data-floor-anchor="center center"`, set from the pointer's floor position. `useFloorPlacement` already places, scales and depth-sorts every floor item each frame. The circle is flattened with CSS `transform: rotateX(…)`, which composes with placement's `translate` and `scale`. Its squash doesn't change with depth. |
| 2D scenes             | The same element, at the pointer, sized in `cqw` of the scene box (a floor unit is `1cqw` at the floor's front), and not sorted, as 2D scenes don't sort players.                                                                                                                                                                                                                                                              |
| Mid-jump              | While a drag is a jump, the avatar follows the pointer lifted (`data-floor-height`; a fixed lift in 2D), with a shadow (a second floor item, the flat circle) left on the floor under it. It lands where the jump lands. The published position stays held at the take-off, as today. With reduced motion, the lift shows without animating.                                                                                   |
| Pointer (user)        | Shown by default. `avatar.feet.pointer: "hidden"` sets `cursor: none` on the viewport while the avatar shows. Elements with their own `cursor` (buttons, dialogs, the HUD) keep it.                                                                                                                                                                                                                                            |
| Feet with area        | The feet are the avatar's footprint: a 5 × 5 grid of points across its disc, in floor units, mapped to the screen (`floorToViewport`). A target's coverage is the fraction of points that `isUnder` it (so floor areas and covering behave as now), measured against the rule's `threshold` (default `1`, as for a camera foot). Only targets whose box the footprint's box overlaps are sampled.                              |
| Threshold change      | Today any point inside counts; with the camera's default of `1`, the whole footprint must be inside. Scenes whose rules expect the pointer's tip may need lower thresholds, which stage 3 checks in every game.                                                                                                                                                                                                                |
| Player effects (user) | Deferred to [996 (player avatars)](996.00.00.prompt%20-%20player%20avatars.md). They need a registry player with a silhouette and states. The outstanding issue is updated to say why it waits.                                                                                                                                                                                                                                |
| Spectators            | The mouse is always player 1 and never a spectator: it has no registry entry.                                                                                                                                                                                                                                                                                                                                                  |

### Stage 2: Drawing the avatar (Opus)

**Brief:**

- `useMouseFeet`'s `onPosition` becomes `onFeet(feet: { point, airborne } | null)`: the live pointer, and whether
  a jump is under way. `usePositionReports` keeps publishing the held take-off, as now.
- New `MouseFeetAvatar` (`src/components/core/layout/MouseFeetAvatar.tsx`), rendered in `DepthStack` while
  `mouseFeet` is on and the pointer is in the viewport, with `pointer-events: none`:
  - 2.5D: the floor item and its shadow, with `data-floor-*` set from `viewportToFloor`, placed by
    `useFloorPlacement`;
  - 2D: positioned at the pointer, in `cqw`;
  - the look from `ResolvedFeet`: the flat circle, or the image standing upright;
  - `data-airborne` and the lift mid-jump; `cursor: none` on the viewport with `pointer: "hidden"`.
- Updates by setting attributes on a ref, not React state, so a pointer move doesn't re-render the layout.
- The CSS (`GameLayersLayout.css`): the circle, its `rotateX`, the shadow, and the lift's transition, off under
  `prefers-reduced-motion`.

**Tests:**

- `tests/MouseFeetAvatar.test.tsx`:
  - nothing before the pointer enters, or after it leaves;
  - in 2D, at the pointer, sized from `size`;
  - in 2.5D, `data-floor-x` and `data-floor-y` from the pointer's floor position;
  - airborne: `data-airborne`, the lift, and the shadow;
  - `imageResource` draws the image; `color` sets the circle's colour;
  - `pointer: "hidden"` hides the cursor, and stops hiding it when the avatar goes.
- `tests/MouseFeetHook.test.tsx`: `onFeet` reports the live pointer and `airborne` through a drag.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run tests/MouseFeetAvatar.test.tsx tests/MouseFeetHook.test.tsx tests/GameLayersLayout.test.tsx`.

### Stage 3: Feet with an area (Opus)

**Brief:**

- `MouseFeet` gets a footprint function, `(point) => ClientPoint[]`: the 5 × 5 grid across the avatar's disc,
  through `floorToViewport` in 2.5D, or in screen pixels in 2D. With none (as in tests that don't set it), the
  footprint is the point, as now.
- `targetsAt` counts the footprint's points that are under each candidate element (rectangles first, then `isUnder`),
  and keeps those at or above the rule's `threshold`. A jump's take-off and landing use the same test.
- Check every game's mouse-feet rules against the new default, and lower a threshold where a rule needs the
  pointer's tip (eg. the rules demo's lava corner). Note each change in the commit.

**Tests:**

- `tests/MouseFeetHook.test.tsx`:
  - with `threshold: 1`, the footprint half over an element doesn't enter it, and wholly over it does;
  - `threshold: 0.5` enters at half;
  - a covered part doesn't count unless `includeCovered`;
  - a jump landing half on an element fires `jump-onto` only if its threshold allows.
- `tests/browser/rules.spec.ts`: the existing mouse-feet tests still pass, with moves adjusted only where a threshold
  changed.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run` + `npx playwright test tests/browser/rules.spec.ts tests/browser/jump-and-duck.spec.ts`.
