Prepare a plan to find out whether an Xbox 360 Kinect (model 1414) can give the game real distance information, and if so to connect it.

This came out of `002.02.00`. [ADR 0010](../ADRs/0010-player-tracking-from-behind.md) recommends against the Kinect for now, because the simpler depth estimate may be enough. Only start this if the real-camera check shows that estimate isn't good enough.

## What we want

The game estimates each player's distance from the bottom of their silhouette. A Kinect measures distance directly, so it could:

- give true depth, for sorting players among foreground items;
- help cut players out of the picture, by separating them from the room by distance.

## What we know so far

Nothing here has been tested on our hardware. The Kinect has not been connected to this laptop.

- **Hardware:** Xbox 360 Kinect, model 1414. It is expected to need its USB and power adapter. Check that we have one.
- **Laptop:** MacBook Pro, M1, running Tahoe.
- **Driver:** `libfreenect` (OpenKinect) supports model 1414. Reports of it on M-series Macs say it works but is flaky. One describes macOS attaching its audio driver to the Kinect, occasionally crashing the machine. We found nothing about Tahoe.
- **Body tracking:** We found no working option on a Mac. Microsoft's SDK is for Windows, and NITE is no longer available. Expect depth and colour pictures only, so a vision model would still find hands, feet and heads.
- **Browser:** A browser can't use it directly, as it doesn't appear as a camera. A separate local program would have to read it and pass its pictures to the page, for example over a WebSocket.
- **From behind:** Depth should work from any side. A model's body tracking on a Kinect picture from behind is untested.
- **Limits, from memory and not checked:** about 0.8–4 m range, indoor light only, and 640×480 pictures at 30 frames per second.

## Questions to answer

### First, with the hardware and no game code

- Does `libfreenect` build and run on this laptop, and stream depth steadily for 30 minutes without a crash?
- Does it see the whole play area from behind and above, including feet?
- How noisy is the depth at a player's feet, and on a dark or shiny floor?

Stop here and report if it can't run reliably.

### Then, if it does

- What's the simplest way to get depth into the page, and how much delay does it add?
- How do we line up its picture with the camera's, or do we use its own colour picture for the cut-out, at a lower resolution?
- How does it fit behind `FootstepsVisionModelImplementation` (`src/vision/`)?
- How will the game behave when the program or Kinect isn't there? It should fall back to the current estimate.
- How is the program installed and started for a play session? It adds a second thing to run alongside the browser.
