Prepare a plan to rename "display" to "scene" across the code base, the documentation, and the game data format.

# Context

"Scene" is a better term for what a game shows at each point, and it's easier to explain in documentation. It also suits the work that follows, which adds scene modes:

This is a rename only. Behaviour must not change.

# What to rename

- **Code:** types, functions, variables, files, CSS classes and ids, test names, and log and validation messages. For example `GameDisplayData`, `DisplayScope`, `getShownDisplays`, `resetDisplay` and `displayKey`.
- **Game data format:** keys such as `displays` and `resetDisplay`, and the JSON schemas generated from the types (`generate-schemas.sh`).
- **Names authors use in templates and rules:** for example the `.display-foreground` and `.display-background` effect targets.
- **Documentation:** the docs in `docs/`, including headings, so links and anchors (eg. `#ending-with-the-display`) need updating too. Typedoc output is regenerated, not edited.
- **Existing games:** Nanny's Magic Trifle, the rules demo, and the test fixtures.

# What to leave alone

- CSS's `display` property, and "display" as an ordinary verb ("displays a message").
- Browser and platform meanings, such as a screen or the Fullscreen API.
- Earlier prompts and plans in `docs/prompts/`, and the titles and filenames of existing ADRs, as a record of what was asked and decided at the time.

# Approach

- **A clean break.** There is one user, and no games outside this repository, so update every game rather than supporting both names. Game data that still uses an old key fails validation with a message naming its new key, as old interaction names already do.
- **Check names that already use "scene".** `.gameScene` wraps the layers that fade together, and `useSceneTransition` fades between displays. After the rename these names describe exactly what they do (scenes fading into each other), so check each one reads correctly rather than renaming them.
- **Not a blind search and replace.** Rename by meaning: the type checker and tests catch code, but docs and game data need reading.
- **Do it alone.** The rename touches nearly every file, so land it in its own branch and PR before 002.03.02 starts, to keep later diffs readable.

# Done when

- Every game in the local repository loads, validates (`validate-repository.sh`) and plays as before.
- An old key in game data fails validation, naming its new key.
- All checks and test suites pass.
