## Context

Plans 000.02 – 000.05 (docs site, landing/fullscreen, camera mode, application tweaks) were implemented by Deepseek (commits from `7b87882` onward, no Claude trailer). The features are accepted; this audit looks for bugs and wider risks, since `npm audit` only covers one class of risk. CI is green on the current branch.

Scope read: everything under `src/` touched since `60dd9f1` (~4.9k lines), the validation scripts, CI workflow, and dependency usage. `magic-trifle` turns the camera on for its stages overview (`hand`/`jump`, threshold 0.5), so camera paths are live, not theoretical.

## Findings

### High

#### H1. A camera that fails to start freezes the game

`CharacterCamera.tsx:34-47` calls `getCameraStream().then(...)` with no `catch`, so the aspect ratio is never reported. `useSceneTransition.ts:143` then waits for it indefinitely, and `GameLayersLayout.tsx:312` hides every layer while it waits.

- Title → stages: the title stays on screen forever, and clicks do nothing because the state has already moved on.
- Continue into a camera display: the screen is blank apart from the HUD.
- Triggers: camera in use by another app (`NotReadableError`), no camera, permission revoked after the landing page, or Safari's per-session `prompt`. The permission guard only checks permission. It doesn't check whether the device actually works.

### Medium

#### M1. Continue replays the reward

`Game.tsx:62-74`: `progressTracker` starts as `[]`. A restored game with completed stages differs from that on the first render, so it fires fireworks and the stage-completed sound. This comes from the 000.05 save/continue work.

#### M2. Music keeps playing after you leave a game, and tracks overlap

`GameMusicProvider.tsx`: tracks are `new Audio()` elements outside the DOM, and nothing pauses them on unmount. Going back to the landing page (new in 000.05) leaves the music playing. Pressing Continue then starts a second track over it. Two `playMusic` calls within the 1s fade also overlap, because `currentMusic` is captured when the call is made.

#### M3. The camera stream leaks, and a null deref is possible

In `CharacterCamera.tsx`, if the component unmounts before `getUserMedia` resolves, the stream's tracks are never stopped and the camera light stays on. `videoRef.current!` can also be null at that point. StrictMode in dev hits this on every mount. `play()` rejections are unhandled.

#### M4. The segmentation loop dies silently

`CharacterCanvas.tsx:139-154`: any throw in `segmentPeople`, `toImageData` or `drawMask` (for example a lost WebGL context, or a video with 0×0 size) rejects the async frame. No new frame is scheduled after that, so the silhouette freezes and camera interactions stop until the page is reloaded.

#### M5. A fresh player monitor fires straight away

`PlayerInteractionHook.ts:75-79` clears the monitors during every transition. A new `PlayerMonitor` has an empty `held` set, so a hand already resting over a stage tile when the stages overview fades back in counts as a new "hand" interaction and enters that stage. The code comment claims the opposite.

### Low → promoted to fix (your call)

- **L1.** The landing page and the guard disagree on `unsupported` permission state. The guard allows play, but the landing page disables the buttons until Grant is clicked. Agreed fix: the guard bounces anything that isn't `granted`.
- **L2.** The wake lock isn't re-acquired if the system releases it while the page stays visible. Agreed fix: re-acquire it, and show a low-battery warning on every page.
- **L3.** The validator doesn't check that `clickIdToStageId` names real stages. A typo makes `enterStage` (`GameClickUtils.ts:76`) throw on click. Agreed fix: the validator checks it.

### Low (record, don't fix now)

- **L4.** No root `ErrorBoundary`. Bad game data that throws during render shows React Router's default error page. Accepted while in development.

### Risks `npm audit` doesn't see

- **S1. Unpinned tools run on every commit, push, CI job and deploy.** These fetch whatever version is latest from npm. They aren't in the lockfile, so neither audit nor `npm ci` covers them. This is the main supply-chain gap.
  - `validate-game.sh:29` and `validate-repository.sh:29` run `npx --yes ajv-cli`.
  - `generate-schemas.sh:7,11` runs `npx --yes typescript-json-schema`; pre-build and pre-commit call this script.
  - CI has two more version sources that live outside the lockfile. It installs `markdownlint-cli@0.49.1` globally. It also hard-codes Node `26` in both workflows, separately from `package.json` `engines`.
- **S2. Unused runtime dependencies.** `@react-hook/resize-observer` and `@fontsource/roboto` are never imported. `@types/lodash` is in `dependencies` rather than `devDependencies`. (`@mui/material` and `@emotion/*` are needed as peers of `@mui/icons-material`.)
- **S3. The sprintf-js advisory may be stale.** `sprintf-js@1.0.3` is still in the tree via tfjs → argparse (`npm ls`), even though audit now reports 0. Either the advisory was withdrawn or it's no longer matched. The `docs/outstanding-issues.md` entry needs re-checking, not deleting blind.
- **S4. Runtime third-party fetches.** The BodyPix weights (~90 MB, Google storage) and the Google Fonts stylesheet load at play time. Offline or during an outage, the camera silently has no silhouette (the model returns null) and fonts fall back. Camera frames never leave the device.
- **S5. Already documented and still accurate:** no strict CSP, remote repositories are untrusted (not reachable from any route today), and TypeScript 7 is blocked.

## Remediation plan

### Stage 0: record the prompt and plan

Following the repo's prompt convention:

- Save the original request, plus the review comments on this plan, as `docs/prompts/000.06.00.prompt - application audit.md`.
- Save this plan as `docs/prompts/000.06.01.plan - application audit.md`.
- Any later feedback/plan pairs become `000.06.02`, `000.06.03`, and so on.
- Fix the reference in the plan file so the docs build resolves it (see `0c5e2b6`).
- Commit both files first, as the earlier plans do.

Each stage is one commit on a new branch off `main` (`000.06.00-application-audit`, stacked on `000.05.00-application-tweaks`). Each stage needs `dev-qual/scripts/check.sh` to pass before moving on.

### Stage 1: camera robustness (H1, M3, M4)

- `CharacterCamera.tsx`: add a `cancelled` flag to the effect, stop the stream's tracks if the effect is cancelled before it resolves, null-check the video ref, and `catch` both `getUserMedia` and `play()`. On failure, call a new `onError` prop.
- `GameLayersLayout.tsx`: keep a `cameraFailed` state. While it's true, pass `{ enabled: false, preview: false }` to `useSceneTransition` instead of `camera`, so the game falls back to click play rather than freezing.
- `CharacterCanvas.tsx`: wrap the body of `segmentFrame` in `try/catch`, log the error, and still schedule the next frame.
- Tests: extend `tests/GameLayersLayout.test.tsx` so that a rejected `getUserMedia` (using the existing `tests/helpers/media.ts`) still advances title → stages. Add a canvas test where `segmentPeople` throws once and the loop keeps reporting.

### Stage 2: feedback and music on resume (M1, M2)

- `Game.tsx`: start `progressTracker` from the initial state's completed stages instead of `[]`.
- `GameMusicProvider.tsx`: hold the current track in a ref as well as state. Pause it in an unmount cleanup, and have `playMusic` read the ref so that rapid calls fade the real current track.
- Tests: rendering `Game` from a restored state doesn't call `reward` or play the stage-completed sound. Unmounting the music provider pauses the track.

### Stage 3: arming the camera monitor (M5)

- `PlayerMonitor.update`: on a monitor's first frame, record what is covered in `held` without emitting anything, so interactions fire only once a body part enters an element. Fix the misleading comment in `PlayerInteractionHook.ts`.
- Test in `tests/PlayerMonitor.test.ts`: a hand covering a target on the first frame emits nothing, and emits once after it leaves and comes back.

### Stage 4: permission guard (L1)

- `GamePermissionUtils.ts`:
  - Record each permission that `requestGamePermission` grants in a module-level `Set`, which lasts for the session.
  - `checkGamePermission` returns `granted` when the browser can't answer the query but the permission was granted this session. Otherwise it returns `unsupported` as now.
- `GamePermissionGuard.tsx`: allow play only when every state is `granted`, and bounce everything else to the landing page. The landing page already requires `granted`, so the two now agree.
- The cost: in a browser that can't query the camera, reloading `/play` lands on the landing page, and the player clicks Grant again. That's the intended behaviour.
- Tests:
  - `tests/GamePermissionGuard.test.tsx`: `unsupported` now redirects.
  - `tests/GamePermissionUtils.test.ts`: an unsupported query after a successful request reports `granted`.

### Stage 5: wake lock and battery warning (L2)

- `WakeLockHook.ts`: in the sentinel's `release` listener, re-request the lock if the hook is still active and the page is still visible.
  - If the request is refused, the existing catch logs it, and the next visibility change tries again. There's no retry loop.
  - `// ponytail:` the ceiling is one retry per release. Add backoff if a browser is seen to release in a loop.
- New `src/components/core/BatteryWarning.tsx`, rendered in `root.tsx`'s `Root` above `<Outlet />` so it shows on every page:
  - It uses `navigator.getBattery()`. Declare the minimal `BatteryManager` and `Navigator.getBattery?` types locally, with no `any`.
  - It shows a fixed, high-contrast banner (`role="status"`) when the level is ≤ 20% and the device isn't charging, and updates on `levelchange` and `chargingchange`.
  - It renders nothing when the API is missing, and during prerender (the API is read in an effect).
- Limitation: the Battery Status API exists only in Chromium browsers (Chrome, Edge, Android). Firefox and Safari show no warning. Record this in `docs/outstanding-issues.md`.
- Tests:
  - `tests/WakeLock.test.ts`: a system release while visible re-acquires the lock, and a release after the hook goes inactive doesn't.
  - New `tests/BatteryWarning.test.tsx`: shown at 15% and discharging. Hidden while charging, above the threshold, or with no API.

### Stage 6: validate stage references (L3)

- `scripts/resource-checks.ts`: add a check that each overview display's `clickIdToStageId[*].stage` names a stage in `game.stages`. Report problems with the existing `{ path, message }` shape, for example `displays[2].clickIdToStageId.stages-link-stage-9.stage`. Include it in `checkGame`, so both `checkRepository` and the CLI get it.
- Tests: add a bad-reference case and a good-reference case to `tests/ValidateResources.test.ts`.

### Stage 7: pin the tooling, with one source of truth (S1, S2, S3)

- The single source is `package.json` and `package-lock.json` for npm tools, and `package.json` `engines` for Node.
  - Add `ajv-cli`, `typescript-json-schema` and `markdownlint-cli` as exact-pinned devDependencies.
  - Switch every `npx --yes` call to `npx --no-install` (the ajv binary is `ajv`), so a missing tool fails instead of downloading one.
  - `check.yaml`: drop the global markdownlint install, and add `node_modules/.bin` to `$GITHUB_PATH` so `check.sh` finds the pinned copy. For local runs, document `npx --no-install markdownlint` or a global install of the same version in `docs/dev-overview.md`.
  - `check.yaml` and `deploy-pages.yaml`: replace `node-version: 26` with `node-version-file: package.json`, which reads `engines.node`.
  - actionlint is a Go binary that runs only in CI. Its version stays pinned in one place, `check.yaml`.
- Remove `@react-hook/resize-observer` and `@fontsource/roboto`, and move `@types/lodash` to devDependencies. Then regenerate the license report (`generate-license-report.sh`).
- Re-check GHSA-hp3w-g68c-fv3c. If it has been withdrawn, close the outstanding-issues entry. Otherwise, add a note on why audit no longer reports it.

## Open decisions (defaults chosen; say if you want otherwise)

- H1 fallback: switching quietly to click play, with only a console warning. A visible "camera unavailable" notice in the HUD would be a small addition.

## Outcome

All stages are done, one commit each. Where the work differed from the plan:

- Stage 4: the per-tab grant is kept in `sessionStorage` rather than a module-level `Set`. That way
  tests start clean, and a reload in the same tab keeps the grant. This also closed the
  outstanding-issues entry about repeated Grant clicks, which proposed the same fix.
- Stage 7: pinning `ajv-cli` showed eight advisories that `npx --yes` had hidden from `npm audit`.
  - `ajv-cli` is unmaintained, and its `fast-json-patch` dependency carried one of them. So
    `scripts/validate-schema.ts` now validates with `ajv` directly, and `ajv-cli` is gone.
  - The rest came from `markdownlint-cli`'s parsers, the same version CI already installed globally.
    They are fixed with scoped `overrides`.
  - `license-report` was also run with `npx --yes`, and is pinned too.
  - Node's version comes from `.nvmrc`, because `engines.node` is a minimum, not a version.
  - The sprintf-js advisory was withdrawn on 2026-10-22, so its entry is closed.
- Stage 8: added the CI runner's unpinned shellcheck to `docs/outstanding-issues.md`.
