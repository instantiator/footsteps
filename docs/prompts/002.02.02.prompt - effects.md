Prepare a plan to implement several new visual effects.

Some of these result in the player being hidden. Others must be used to restore the player. This will involve other conditions.

## Quake effect

This is a fairly simple implementation.

Extend `GameAction`, adding `GameEffect` - one of which should be the quake effect.

Intended for use when the user completes a specific jump (ie. an effect attached to a jump completion) or any jump.

Example - effect is applied to a single element

```json
{
    "on": {
        "interact": ["jump-from"],
        "target": "#some-element",
    },
    "do": [
        { "effect": "quake", "target": "#some-element", "dx": 10, "dy": 0, "duration_ms": 1000, "easing": "some-css-easing-function" }
    ]
},
```

- `animation`: the effect applied to the element
- `target`: if present, applied to the elements identified by the selector; if not present, applied to all elements across background and foreground layers
- `dx`: amount to shake horizontally
- `dy`: amount to shake vertically
- `duration_ms`: duration of the effect
- `easing`: a CSS easing function (optional, default: `undefined`) - this affects the easing-in and easing-out of `dx` and `dy` (if not defined, use full `dx` and `dy` as specified)

## Item fall effect

> [!NOTE]
> This could already be implemented with variables, as seen in the rules demo game, but this is more meaningful and easier to understand when composing games.

```json
{
    "on": {
        "interact": ["jump-from"],
        "target": "#some-element",
    },
    "do": [
        { "effect": "item-fall", "target": "#some-element", "duration_ms": 1000, "easing": "some-css-easing-function" }
    ]
},
```

- `animation`: the effect applied to the element
- `target`: (optional) if present, applied to the elements identified by the selector; if not present, applied to all elements across background and foreground layers (not recommended for this item!)
- `duration_ms`: duration until the element has left the display (optional, default: `1000`)
- `easing`: a CSS easing function (optional, default: `linear`)

## Item move effect

> [!NOTE]
> This could already be implemented with variables, as seen in the rules demo game, but this is more meaningful and easier to understand when composing games.

```json
{
    "on": {
        "interact": ["jump-from"],
        "target": "#some-element",
    },
    "do": [
        { "effect": "item-move", "target": "#some-element", "duration_ms": 1000, "start": { "top": 100, "left": 50 }, "end": { "top": 50, "left": 50 } }
    ]
},
```

- `animation`: the effect applied to the element
- `target`: if present, applied to the elements identified by the selector; if not present, applied to all elements across background and foreground layers (not recommended for this item!)
- `duration_ms`: duration of the move
- `destination`: target position for the item
- `easing`: a CSS easing function (optional, default: `linear`)

## Highlight effect

```json
{
    "on": {
        "interact": ["near"],
        "target": "#some-element",
        "within": "distance"
    },
    "do": [
        { 
          "effect": "highlight", 
          "target": "#some-element",
          "sequence": [ 
            { 
                "filter": "some-css-filter", 
                "shadow":  "some-css-shadow-properties", 
                "outline": "some-css-outline",
                "border": "some-css-border",
                "duration": 1000,
                "easing": "some-css-easing"
            }
          ],
          "easing": "some-css-easing-function"
        }
    ]
},
```

- `sequence`: a series of highlight effects
  - `filter`: (optional)
  - `shadow`: (optional)
  - `outline`: (optional)
  - `border`: (optional)
  - `duration`: (optional, default 1000)
  - `easing`: (optional, default `undefined`)

## Player state

Player state changes need to be tracked, so that these changes can be implemented.

Some of the effects described here result in players being removed from the display. This will require stable tracking of players over time. If this can't currently be achieved, challenge this part of the prompt during planning.

### Restore

By default, when a display resets, any 'removed' players are also reset (ie. becomes visible again).

The game should track active players as an additional variable that can be used as a trigger for rules to manage cases like "all the players fell" (ie. when active players reaches 0, the display should reset).

### Falling effect

It should be possible to apply a falling effect to a player - their particular canvas should be moved downards until off-screen. Similar properties as found on the `item-fall` effect.

The player keeps their distance property.

From the moment the player starts to fall, they should not be able to interact with any items in the display.

Once off screen, the player should be marked as removed from the display.

### Spin away effect

This follows a similar pattern, but the player leaves the screen in a random direction with an upward motion, their canvas rotates as if they have been knocked.

### Invisible/Visible

These are shorthand for changes to the player's opacity.

### Static

This applies an effect that uses a static effect to make the player seem to be partially transparent. The mask for this should have configurable pixel size, with a sensible default, and a target proportion of the player's pixels made transparent. The effect should ease in and out by altering the proportion of transaprent pixels.

## Duration modifiers

Duration for most effects will be set to a number of ms, but for some it will be continuous. To achieve this: `duration` should be typed as `number | "indefinite"`

If `indefinite` any animation applied to the element should loop when it completes.

## Delay

All actions should gain an optional `delay` property that allows the effect or action being applied to be delayed by a number of ms. (Optional, default 0.)
