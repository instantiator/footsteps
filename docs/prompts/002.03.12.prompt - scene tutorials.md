Prepare a plan to write tutorials for building scenes.

# Context

Prompts [002.03.02](<002.03.02.prompt - scene and avatar modes.md>) to [002.03.10](<002.03.10.prompt - new games and badges.md>) add scene and avatar modes, calibration, floor-placed items, floor areas, walls and backgrounds, players' positions as variables, new rules, and new games. The reference docs (`game-data.md`, `camera-mode.md`, `special-effects.md`) say what each piece does, but not how to put them together into a scene. Tutorials should fill that gap.

"Your first game" comes first, and the scene tutorials build on it.

The readers are game authors: comfortable editing HTML, CSS and JSON, but not necessarily familiar with Footsteps' code.

# Recommendations

- **Build each tutorial on a game in the repository.** Each one walks through a real scene, step by step, so its examples are known to work and stay checked by the game's validation and browser tests. Quote the game's files rather than writing separate examples that can drift.
- **Start each from nothing.** Each tutorial begins with an empty scene and adds one thing at a time, saying what to look for on screen after each step, including what `?debug=true` shows.
- **Link, don't repeat.** Tutorials explain how to put things together, and link to the reference docs for every attribute, class and rule, so there's one place to update.
- **Where they live.** A `docs/tutorials/` folder, listed in `docs/index.md` and published with the rest of the docs.
- **Illustrations.** The 2.5D tutorial will want diagrams of floor coordinates and of the surfaces around the floor. Reuse or adapt those in `docs/prompts/illustrations/`.

# Not included

- **Calibrating a room.** Players shouldn't need a tutorial: the calibration view itself explains what to do (see [002.03.04](<002.03.04.prompt - calibration.md>)).

# Done when

- Every game in the local repository loads, validates and plays.
- Each tutorial's quoted files match the game it's built on.
- `docs/index.md` lists the tutorials.
