### Security

Remote game repositories supply templates, styles and (new) stylesheets. The site has no logins or cookies; the risks are injected script, fake UI/forms, and tampering with saved state in localStorage. Handlebars compiles templates with `new Function`, and its maintainers don't treat compiling untrusted templates as a security boundary, so we harden in-page (agreed; a sandboxed iframe is the stronger option, not in scope):

- **Template output:** `DOMPurify.sanitize(html, { FORBID_TAGS: ["form"] })` — strips `<script>`, `on*` handlers, `javascript:` URLs and forms.
- **Handlebars:** `compile(…, { knownHelpersOnly: true })` (no helpers registered yet), no `compat`, prototype access left off (default since 4.6), pinned ≥ 4.7.7 (fixes for the known compile CVEs).
- **Stylesheets:** a resolved href is used only if its protocol is `https:` or it's same-origin; otherwise skipped with a `console.warn`.
- **CSP:** `<meta http-equiv="Content-Security-Policy" content="object-src 'none'; base-uri 'self'; form-action 'none'">` in `src/root.tsx`.
- **Deferred:** a strict `script-src` (React Router's prerendered inline scripts need per-build hashes, and Handlebars needs `'unsafe-eval'`). Recorded in `docs/outstanding-issues.md` with the condition: act when a game repository from an untrusted author is supported, or the app gains logins/cookies.
