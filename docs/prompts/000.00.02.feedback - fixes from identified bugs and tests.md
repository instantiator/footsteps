# Fixes from identified bugs and tests

Potential bugs found while documenting and testing, for prompt 000.00.00. All 19 actions below are now done, and every test that was skipped for them now runs and passes. The **Test** lines describe the state before the fixes.

Severity: **high** means a player or game author will hit it. **Medium** means a game-data field or a code path silently does nothing. **Low** means an edge case or a cosmetic problem.

## Process

The work is on branch `000.00.02-fixes-from-identified-bugs`, which is stacked on `000.00.00-documentation-and-fixes`.

Create a TODO for each item. Then for each TODO:

1. Present it to the user, and offer options to resolve it to the user (and a recommendation)
2. Note the user's preference as an additional `- **Action:**` item in its list

When the user has selected a course of action for all items, implement the selected fixes.

## 1. Numeric container style values crash template rendering (high)

- **Where:** `src/components/core/display/GameDisplayTemplateComponent.tsx`, `containerStyleParsed`
- **Intent:** style values can be Mustache templates over the template data.
- **Actual:** every value is passed to `Mustache.render`, which throws for anything that isn't a string. So a valid `CSSProperties` value such as `zIndex: 2` or `opacity: 0.5` crashes the display.
- **Test:** `tests/GameDisplayTemplateComponent.test.tsx`, "applies numeric container style values" (skipped)
- **Action:** Render only string values with Mustache. Pass numbers and `undefined` through unchanged. Throw an error naming the style key and the value's type for anything else.

## 2. Only container styles are Mustache-rendered, not template styles (low, needs a decision)

- **Where:** `src/components/core/display/GameDisplayTemplateComponent.tsx`
- **Intent:** unclear. `containerStyle` values are rendered as Mustache, but `templateStyle` values are passed through unchanged.
- **Actual:** a `{{…}}` in `foregroundTemplateStyle` or `backgroundTemplateStyle` reaches the DOM literally.
- **Test:** `tests/GameDisplayTemplateComponent.test.tsx`, "renders template style values as Mustache templates over the data" (skipped)
- **Action:** Render template style values with Mustache too, using the same helper as container styles.

## 3. `config.autoAdvanceStages` is never read (medium)

- **Where:** `src/entities/data/GameData.ts` (field), `src/components/core/logic/GameStateUtils.ts` `completeChallenge`
- **Intent:** a game author controls whether finishing a stage moves straight to the next one.
- **Actual:** the code decides from whether the game has a `game-overview-stages` display, and the field has no effect.
- **Test:** `tests/GameStateUtils.test.tsx`, "advances straight to the next stage when config.autoAdvanceStages is true" (skipped)
- **Action:** Honour it. `true` goes straight to the next incomplete stage. `false` or absent keeps the current rule: return to the stages overview if there is one, otherwise advance.

## 4. Solution `hints`, `autoAccept`, and scroll `hint` are never used (medium)

- **Where:** `src/entities/data/GameChallengeSolution.ts` (`hints`, `autoAccept`, `DEFAULT_GAME_CHALLENGE_SOLUTION_PROPS`), and `src/entities/data/displays/GameDisplayScrollComponentData.ts` (`hint`)
- **Intent:**
  - hints are offered in order on request
  - `autoAccept: false` makes the player confirm a matching answer
  - a scroll page can show a hint
- **Actual:**
  - nothing reads these fields, and `hints` is even required by the schema
  - `DEFAULT_GAME_CHALLENGE_SOLUTION_PROPS` is unused, and `validateAnswer` hard-codes the same defaults
- **Test:** none. These are missing features, not testable behaviour.
- **Action:** Remove all four: `hints`, `autoAccept`, the scroll page `hint`, and `DEFAULT_GAME_CHALLENGE_SOLUTION_PROPS`. Take them out of the types, the schemas, and the magic-trifle and test data. Re-add them when a feature needs them.

## 5. Challenge state `displayPurpose` and `attempts` are never updated (medium)

- **Where:** `src/entities/state/GameChallengeState.ts`, `src/entities/state/GameState.ts` `createBlankGameState`, `src/components/core/logic/RenderDataUtils.ts` `calcChallengeDisplay`
- **Intent:** a challenge moves through `challenge-title` → `challenge-in-progress` → `challenge-completed` displays, and records the player's attempts.
- **Actual:**
  - `displayPurpose` stays `null`, so `calcChallengeDisplay` always prefers `challenge-title` when there is one
  - the in-progress and completed displays are never shown alongside it
  - `attempts` is never appended to
- **Test:** `tests/RenderDataUtils.test.ts`, "shows the completed display once the challenge is succeeded" (skipped)
- **Action:** Derive the display from `succeeded`, and drop the `displayPurpose` and `attempts` state. An unsolved challenge shows title, then in-progress, then completed, whichever it has first. A solved one shows completed, then in-progress, then title.

## 6. With `autoSubmit` off, an answer can never be submitted (high)

- **Where:** `src/components/core/display/GameTextInputComponent.tsx`
- **Intent:** `autoSubmit: false` means the answer is submitted explicitly, on Enter or a button, instead of on every keystroke.
- **Actual:** the input only submits from `onChange` when auto-submit is on. There is no Enter handler and no button, so the answer can never be checked.
- **Test:** `tests/GameTextInputComponent.test.tsx`, "submits the typed answer on Enter when autoSubmit is off" (skipped)
- **Action:** Submit on Enter: wrap the input in a `<form>`, and when `autoSubmit` is off, Enter submits the answer.

## 7. "To title" shows for games with no title display (medium)

- **Where:** `src/components/core/HeadsUpDisplay.tsx`
- **Intent:** offer a return to the title screen when the game has one and it isn't showing.
- **Actual:** the button shows whenever the overview isn't the title. In a game with no `game-overview-title` display, pressing it selects a display that doesn't exist, and the overview layer goes blank.
- **Test:** `tests/HeadsUpDisplay.test.tsx`, "does not offer 'To title' in a game with no title display" (skipped)
- **Action:** Only offer "To title" when the game has a `game-overview-title` display and it isn't showing.

## 8. Game state isn't reset when the game changes (medium)

- **Where:** `src/providers/GameStateProvider.tsx`
- **Intent:** the state belongs to the game being played.
- **Actual:**
  - `useState(createBlankGameState(gameData))` only uses its initial value on first mount
  - React Router reuses the route component when going from `/game/a` to `/game/b`, so the old game's state, and therefore its data, keeps showing
  - `createBlankGameState` also runs on every render, because it isn't passed lazily
- **Test:** `tests/GameStateProvider.test.tsx`, "resets to the new game's blank state when the game changes" (skipped)
- **Action:** Remount `GameStateProvider` per game (`key={gameId}`, inside `GameDataProvider`), and initialise the state lazily: `useState(() => createBlankGameState(gameData))`.

## 9. Game ids that match `Object.prototype` keys count as found (low)

- **Where:** `src/providers/GameDataProvider.tsx`, `repository.games[id]`
- **Intent:** an unknown id gives `not-found`.
- **Actual:** `/game/constructor`, `/game/toString` and similar ids find a function on `Object.prototype` and try to render it as a game.
- **Test:** `tests/GameDataProvider.test.tsx`, "reports not-found for the inherited key %s" (skipped, for `constructor` and `toString`)
- **Action:** Look the game up only when `Object.hasOwn(repository.games, id)`.

## 10. `GameChallengeGrid` adds the class "undefined" (low)

## 11. `findFeet` ignores the top row of the mask (low)

- **Intent:** the feet band covers up to `FEET_BAND_ROWS` rows ending at the lowest opaque row.
- **Actual:** row 0 is never counted. A mask whose only opaque pixels are in row 0 gives `null`, although `lowestY` found them.
- **Test:** `tests/CameraSupport.test.ts`, "finds feet when the only opaque pixels are in the top row" (skipped)

## 12. The closing music is skipped if the opening music is still playing (low, needs a decision)

- **Where:** `src/providers/GameMusicProvider.tsx` `playMusic`, called from `useGameFeedback` in `src/components/core/Game.tsx`
- **Intent:** tracks don't play over each other.
- **Actual:** `playMusic` refuses while any track plays, rather than replacing it. Finishing the game while the opening track is still playing means the closing track never plays.
- **Test:** none until the behaviour is decided. `tests/GameMusicProvider.test.tsx` covers the current refuse-while-playing behaviour.
- **Action:** Replace the current track. Fade it out by stepping `audio.volume` down on a timer over about 1 second, pause it, then start the new track. iOS Safari ignores `volume`, so there the old track stops abruptly. Update the music tests to expect replacement.

## 13. Failed fetches are treated as successful (low)

- **Where:** `src/providers/GameRepositoryProvider.tsx`, and `fetchTemplate` in `src/providers/GameContentCacheHook.tsx`
- **Intent:** a failed fetch is reported as a failure.
- **Actual:** neither checks `response.ok`.
  - A repository fetch that returns 404 or 500 with a body that parses as JSON is treated as a ready repository, holding whatever the body holds.
  - A missing template's 404 page is cached and rendered as the template.
  - Two displays asking for the same uncached template at the same time fetch it twice.
- **Test:** `tests/GameRepositoryProvider.test.tsx`, "reports an error status response with a JSON body as not ready, with the error" (skipped)
- **Action:** Check `response.ok` in both fetches, and throw on failure so the repository becomes failed and a missing template renders nothing. Also de-duplicate concurrent template fetches by caching the in-flight promise.

## 14. Feature flags are recomputed on every render (low)

- **Where:** `src/providers/FeatureFlagsProvider.tsx`, `useMemo(..., [props, searchParams])`
- **Intent:** the flags are only recomposed when they change.
- **Actual:** `props` is a new object on every render, so the memo never hits. The context value changes identity, and every consumer re-renders with it.
- **Test:** none. This is a performance issue, not observable behaviour.
- **Action:** Remove the `useMemo` and compose the flags on every render.

## 15. Debug mode never shows the coloured silhouette (low)

- **Actual:** `debug` is never passed in, so the mask is always binary.
- **Test:** `tests/GameLayersLayout.test.tsx`, "tints the camera silhouette by body part when debugging" (skipped)

## 16. The camera segmentation loop is never stopped (medium)

- **Where:** `src/components/camera/CharacterCanvas.tsx`, the segmentation `useEffect`
- **Intent:** the per-frame segmentation runs while the canvas has a model, a video and a stream, and stops when any of them changes or the canvas unmounts.
- **Actual:**
  - The `requestAnimationFrame(segmentFrame)` loop has no cancel flag. Every re-run of the effect starts another loop, and old loops keep calling the model, which the other effect has already disposed.
  - The cleanup stops the webcam's tracks on any dependency change, not just on unmount, for example a new `onFeetPositionsChange` or `maskType`. Nothing restarts the tracks, so the camera feed dies.
- **Test:** no test: needs TensorFlow, WebGL and a media stream, which jsdom doesn't have.
- **Action:** Fix now. Give the segmentation loop a cancelled flag, and cancel its animation frame in the effect's cleanup. Remove the track-stopping from `CharacterCanvas`, since `CharacterCamera` owns the stream and stops it. Check it by hand with `?debug=true` on a camera-enabled game.

## 17. Templates escape HTML, but the code suggests they shouldn't (low, needs a decision)

- **Where:** `src/components/core/display/GameDisplayTemplateComponent.tsx`
- **Intent:** unclear.
  - `MUSTACHE_OPTIONS` disables HTML escaping, but it's only passed to the container-style rendering, where escaping would corrupt CSS such as `url('…/x.png')`.
  - The template body is rendered by `react-mustache-template-component`, which calls `Mustache.render(template, data)` without options, so `{{value}}` is escaped there.
- **Actual:** `{{value}}` is escaped in templates and not in container styles. A template that needs markup from data has to use `{{{value}}}`, as `docs/game-data.md` now says. Decide whether templates should escape, and if they shouldn't, pass the options through.
- **Test:** `tests/GameDisplayTemplateComponent.test.tsx`, "does not escape HTML in the data, so data can contribute markup" (skipped). If the decision is to keep escaping, rewrite it to expect escaped output.
- **Action:** Keep escaping. Rewrite the test to assert that `{{value}}` is escaped and `{{{value}}}` isn't.

## 18. `DecoratedGameState.stages` isn't typed as decorated stages (low)

- **Where:** `src/components/core/logic/TemplateUtils.ts`, `DecoratedGameState = GameState & { stages: DecoratedStageState[] }`
- **Intent:** code that reads the decorated state sees each stage's `index`, `oneIndex` and `show*` flags.
- **Actual:** intersecting the two `stages` array types means `decorated.stages[i]` is typed as the undecorated `GameStageState`, so callers have to re-type it, as the tests do. `Omit<GameState, "stages"> & { stages: DecoratedStageState[] }` would fix it. This doesn't affect templates at runtime.
- **Test:** none. This is a type-level issue; `tests/TemplateUtils.test.ts` works around it with `decoratedStages`.
- **Action:** Define it as `Omit<GameState, "stages"> & { stages: DecoratedStageState[] }`, and remove the test workarounds.

## 19. An explicitly undefined feature-flag prop removes the default (low)

- **Where:** `composeFeatureFlags` in `src/providers/FeatureFlagsProvider.tsx`
- **Intent:** a prop that isn't given leaves the flag at its default.
- **Actual:** `{ ...defaultFlags, ...props }` copies `debug: undefined` over the default, so `<FeatureFlagsProvider debug={undefined}>` gives a flag that is neither true nor false.
- **Test:** `tests/FeatureFlagsProvider.test.tsx`, "keeps the default for a flag prop that is explicitly undefined" (skipped)
- **Action:** Merge only the defined props over the defaults.
