## Context

`validate-game.sh` and `validate-repository.sh` only check a data file against its JSON schema. A schema-valid file can still name a resource file that is not there, or a URL that does not load, and the game fails at runtime with `resource-error`. The prompt asks both scripts to check the declared resource paths and URLs after schema validation.

Resources and templates come from `resources[*].target` and display template sources, and are resolved the way the app resolves them (`resolveResources` in `src/providers/GameDataProvider.tsx`, `resolveRelativeURL` and `getBaseURL` in `src/util/ObjectUtils.ts`, `resolveTemplateURL` in `src/providers/GameContentCacheHook.tsx`). The same JSON also refers to resources by name (`sounds`, `stylesheets`, `imageResource`, page `media`), which the schema cannot check.

### Decisions taken

| Decision                    | Choice                                                                                                                                                                |
| --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Check scope                 | File and URL existence, plus resource-name integrity for `sounds`, `stylesheets`, `imageResource` and page `media`                                                    |
| URL checks                  | On by default; `--skip-urls` opts out. `run-tests.sh` passes `--skip-urls` so the test run stays hermetic and offline-safe                                            |
| Utility                     | `scripts/validate-resources.ts` (CLI) and `scripts/resource-checks.ts` (pure logic), native Node 26 TypeScript, no new dependencies                                   |
| Local targets               | Resolved against the site root (`--site-root`, default `public/`)                                                                                                     |
| Relative targets            | Resolved against the repository file's directory (repository mode) or the site root (game mode, where no repository location is known); `--repository-root` overrides |
| Aislop of template contents | Out of scope: scanning `{{resources.x}}` inside templates cannot handle dynamic lookups reliably; recorded as an outstanding issue                                    |

### Constraints and reuse

- AGENTS.md: no `any` or type escapes, intent comments, zero lint and type warnings, only change what is asked.
- Reuse the resolution semantics above; do not import `ObjectUtils`, which reads `window`.
- Node 26 runs `.ts` directly (`process.features.typescript === "strip"`), so value imports need explicit `.ts` extensions, types must be erasable, and there is no build step.
- The schemas are regenerated by `generate-schemas.sh`, which both scripts already call before validating.
- Tests live in `tests/` (the vitest `include`), and `tsconfig.vitest.json` must list `scripts` for imports from there.

### Stage 1: Resource-check utility and tests (single model)

**Brief:** Create `scripts/resource-checks.ts` and `scripts/validate-resources.ts`; add `scripts/**/*.ts` to `tsconfig.node.json` (and `erasableSyntaxOnly: true`); add `scripts` to `tsconfig.vitest.json`'s include so tests can import the logic.

`resource-checks.ts` has no I/O of its own. It takes injected `fileExists` and `request` functions, walks a `GameData` (overview, stage and challenge displays; both template sources; `dialog.imageResource`; `contents[*].media`; `sounds`; `stylesheets`), resolves targets, and returns `{ problems, checked }`. `resolveTargetOnDisk` rejects absolute targets and any target that resolves outside its root. URL targets must be absolute `http:`/`https:`; with `skipUrls` the format is still checked but no request is made. Repeated targets are checked once.

`validate-resources.ts` is the CLI:

```text
node scripts/validate-resources.ts repository <repo.json> [--site-root public] [--repository-root <dir>] [--skip-urls]
node scripts/validate-resources.ts game <game.json> [--site-root public] [--repository-root <dir>] [--skip-urls]
```

It reads the JSON, supplies `fs.stat`/`fetch` adapters, prints each problem with its JSON path and resolved path or URL, prints a summary, and exits 1 on problems and 2 on bad usage. URL requests use `GET` with `Range: bytes=0-0`, cancel the body at the headers, follow redirects and time out after 10 seconds.

**Tests** (`tests/ValidateResources.test.ts`): local target resolves under the site root and relative under the repository root; absolute and escaping targets rejected; existing files pass; a missing local file reports its JSON path and resolved path; embedded templates skipped, local/relative/url templates checked and a missing one reported; a 200 URL passes, a 404 and a network error report differently, a non-http scheme fails without a request, `skipUrls` makes no request; undefined sound, stylesheet, `imageResource` and media names each reported and defined names pass; repository mode prefixes `games.<id>.` and checks every game; a repeated URL is requested once; counters match.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run tests/ValidateResources.test.ts`. Expected: both pass with no warnings.
