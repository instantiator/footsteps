## Context

002.03.06 placed items on the calibrated floor. This prompt adds surfaces drawn in the floor's perspective: floor tiles, walls, backgrounds, the ground and the horizon. The engine maps each surface's box onto its on-screen quad with a CSS `matrix3d`. You also asked for:

- Nanny's Magic Trifle's stepping-stones overview to use them: the river as the floor background, the riverbank as the rear wall, the forest as the rear background, and the sky as the horizon.
- The demo to use them in its floor-based stages.

| Decision                           | Choice                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trifle art                         | Cut four new PNGs from `blank-river.png` with ImageMagick (`magick` is installed): river, bank, forest and sky, with the sky made transparent where layers overlap.                                                                                                                                                                                      |
| Trifle scope                       | The **overview** and every stage's **shared scene** (which reuse the stones template), all from one background template file, `overview/background.hbs`.                                                                                                                                                                                                 |
| Demo scope                         | **Walk around** gets the full set. **Lava** and **stone hop** turn their pools and stones into floor areas. The title, the overview, **balloons** and **effects** get a horizon and ground backdrop.                                                                                                                                                     |
| Projection                         | One pure function maps the box to the quad as a homography. It reuses `squareToQuad`, generalised from `Corners` to any four points, composed with a 1/width, 1/height scale, and is written out as a `matrix3d` with `transform-origin: 0 0`. There is no new dependency.                                                                               |
| Upright surfaces                   | Each floor point is raised by `height × row length / 100`, the same rise `placeOnFloor` uses, which gets factored out and shared. The raised edge is still a straight line, because the rise is projective along the edge. Walls and backgrounds share this one function.                                                                                |
| Wall height                        | `data-floor-height` sets it, in the units the prompt names. With no height given, a wall stands as high as the floor is wide.                                                                                                                                                                                                                            |
| Horizon                            | It is the image of the floor's line at infinity: the third row of the inverse homography, carried into viewport fractions through the crop placement (and mirror). With no vanishing point (an affine floor), there is no visible horizon.                                                                                                               |
| Ground and backgrounds at infinity | `ground-background` stops a fixed distance short of the horizon, so `w` never reaches 0. `ponytail:` the cut-off is a constant; if a gap shows on a steep camera, measure it in pixels instead. Backgrounds extend sideways and upwards until their quad covers the viewport's edges.                                                                    |
| Painting order                     | z-index by kind, within the surface's own layer: horizon < ground < rear, left and right backgrounds < `floor-background` < floor areas < items. In the challenge foreground (`.depthStack`), the rear, left and right walls go just below `depthZIndex(0)` and the front wall just above `depthZIndex(100)`. Elsewhere, walls go above the floor areas. |
| Layout                             | A base rule in `GameLayersLayout.css`, using `:where(...)` so authors can override it, sets surfaces to `position: absolute; left: 0; top: 0; transform-origin: 0 0`. The box's size is the author's (100% by default) and sets how the content stretches. The engine still subtracts the layout offset, as items do.                                    |
| One loop                           | Surfaces are placed in the existing rAF loop in `useFloorPlacement`, with no second loop. The properties it sets are cleared the same way.                                                                                                                                                                                                               |
| Feet on floor areas                | `FloorBand` is generalised to a floor **region** `{left, right, back, front}`, and a thickness band is a region across the full width. Camera players: `targetsInReach` tests x as well as y. Mouse-feet: `isUnder` tests the pointer's floor point against a floor area's region, instead of its bounding box.                                          |

### Stage 1: Surface geometry

**Brief:** in `FloorGeometry.ts`, add pure functions with TSDoc. Every quad is in viewport pixels, ordered top left, top right, bottom right, bottom left, as the box's corners are.

- Generalise `squareToQuad` to take any four points, using the `Corners` shape as the quad type (`Quad = Corners`, documented).
- `floorAreaQuad(view, viewport, {left, back, right, front})`.
- `uprightQuad(view, viewport, base: [Point, Point], height)`: the floor points raised by `rise`. Share `rise` with `placeOnFloor`.
- `wallQuad(view, viewport, side, height, distance)`: rear is `y = −distance` across x 0–100; left is `x = −distance` along y 0–100, and so on. The front wall is at `y = 100 + distance`.
- `horizonLine(view): [Point, Point] | undefined`, in viewport fractions, where the line crosses x = 0 and x = 1.
- `backgroundQuad(view, viewport, side, distance)`: `uprightQuad` on the line at that distance. It is extended along the line until the base passes the viewport's sides (rear) or bottom (sides), and it is tall enough that the top edge clears the viewport's top.
- `groundQuad(view, viewport)`: the floor plane from below the viewport's bottom and beyond its sides, back to `GROUND_CUTOFF` (a constant, in floor y units, behind the back edge).
- `horizonQuad(view, viewport)`: from the horizon line up past the viewport's top, with its top edge parallel to the horizon. Undefined when there is no horizon.
- `matrix3dFor(box: MaskSize, quad): string`.

**Tests** (`tests/FloorGeometry.test.ts`):

- `matrix3dFor` maps the box's four corners onto the quad, checked by applying the matrix.
- A floor area of 0 0 100 100 gives the floor's own corners in the viewport.
- With the default corners, the horizon is level and about 3% below the viewport's top.
- An asymmetric calibration (one back corner dragged down) slants the horizon, and the horizon quad slants with it.
- A wall's top edge is its base raised by `height × ratio`, and the rear wall's base is the back edge.
- `backgroundQuad` covers the viewport's sides and top, and stands further back than a wall (its base is higher on screen).
- Every corner of `groundQuad` has `w > 0`.
- Mirroring swaps the left and right walls on screen.

**Gate:** `check.sh --fast` and `npx vitest run tests/FloorGeometry.test.ts`.

### Stage 2: Drawing surfaces

**Brief:** in `FloorPlacement.ts`, or a sibling `FloorSurfaces.ts` if that file would pass ~250 lines:

- `SURFACE_SELECTOR`: `[data-floor-area]` plus the eleven classes.
- `parseSurface(element)` → `{kind, area?, height?, distance}`, or null if `data-floor-area` isn't four finite numbers. The distance defaults to 0 for walls and `BACKGROUND_DISTANCE = 50` for backgrounds, to be tuned in stage 6.
- `placeSurface(element, view, viewport)` sets `transform` to `matrix3dFor(box, quad)` and sets z-index per the decisions. The box is the element's `offsetWidth`/`offsetHeight`. The loop also runs this over `SURFACE_SELECTOR`, and the property list gains `transform`.
- `GameLayersLayout.css`: the `:where(...)` base rule for surfaces (absolute, top/left 0, 100% × 100%, `transform-origin: 0 0`).
- `useUnreachableWarnings` skips floor areas.

**Tests** (`tests/FloorPlacement.test.ts`):

- `parseSurface` handles each class, an area, a bad area (null), and the distance defaults.
- The z-index order: horizon < ground < backgrounds < floor background < areas, with the rear wall below and the front wall above `depthZIndex` in the depth stack.
- A jsdom placement sets a `matrix3d` transform, and stopping clears it.

**Gate:** `check.sh --fast` plus those tests.
