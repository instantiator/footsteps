Currently, we are using a Tensorflow body-segmentation model: BodyPix with the ResNet50 backbone.

See: `src/components/camera/CharacterCanvas.tsx`

This has been _adequate_ for testing, but we need something more performant and more accurate to play games with.

- the frame rate isn't great
- the resolution is pretty low
- the accuracy of body segment identification seems to fluctuate
- it can be confused by the background
- it struggles with multiple players

## Suggested approach

We'll keep the original model, and explore:

- optimisations
- additional models

### Config implementation

Propose a way to store and use application-level config, eg. one or more `.env` files for the various environments:

- `.env.dev` (ie. for `npm run dev`)
- `.env.test` (ie. for `npm run test`)
- `.env.prod` (ie. for the static build)

These config files should work locally, and in CI.

The goal here is to be able to define the model (and other config items, eg. the debug flag) at application level, allowing a user to reconfigure by tweaking config.

Config should be strongly typed, and available through a provider to the application. It should permit flags passed in by the user (eg. `?debug=true`) to override config items.

### Optimisations

What would help to improve the accuracy of the body part recognition, and stability from frame to frame? (Anything?)

### Alternative models

In the past year or so, there has been an increase of pace in development and release of both generative and traditional models to support vision. It's possible there are better models available, that can run more efficiently, and generate better data.

Recommend one or more alternative models that could improve the performance and quality of the recognition.

Requirements:

- can run locally
- runs fast, locally (we are using a modern browser on an M1 Mac with 16Gb RAM to test)
- can identify body parts
- can do whole body identification (ie. not just torso & head)
- ideally
  - not confused by the background
  - can handle more than 1 person

### Abstract interface

Abstract away the work of the model into a `FoostepsVisionModelImplementation` interface / base class, so that:

- any (appropriate) class that implements the interface / inherits from the base class can be used
- the results are marked with body segment identifiers
- key points are calculated by the model implementation class (either directly from the model, or calculated)
  - centre of each foot
  - centre of each hand
  - top, bottom, left, and right of head
- a function to return body types (if any) for a given point
- a function to return body types (if any) for a given area
  - returning (for each found) the proportion of the body part that is inside the area (eg. 50% of the hand is in the box)
- config can be used to control model parameters (eg. resolution, etc.)

We should use our own body segment identifiers, as an abstraction to help shift away from dependency on BodyPix/ResNet50.

The parts we care about are similar, so let's start with a duplicate of the current body parts as an enum. Where there are models that do things differently may need to map their own body parts to this (or we may decide to amend the enum).

### Adapt existing code

Having developed this shared interface, we'll need to adapt the current implementation to work through this.

### Implement new model(s)

For each agreed new model, we should implement another instance of the shared interface, and allow the user to select and configure the new model through config.
