Camera mode is intended to be a part of some game displays.

In future, it will need to be much more configurable. For now, it should be enough to be able to switch it on and off per display (with an overall game default setting for where it isn't set - as we have now, eg. magic trifle leaves it disabled).

NB. There isn't a way to interact with a challenge through camera mode yet... This prompt introduces some basic ways to interact. We'll develop more sophisticated logic and interactive objects in future rounds of development.

## Camera mode

- It should be possible to enable or disable camera mode per display (with fallback to the game default)
- It should be possible to enable or disable the camera preview overlay per display (with fallback to the game default)

### Interactions

At current time, clicks on items are mapped to stage id with `clickIdToStageId`.

Clicks should remain supported, but it ought to be possible to specify additional actions:

```json
"clickIdToStageId": {
  "stages-link-stage-1": {
    "stage": "stage-1",
    "interactions": [ "click", "hand", "foot", "body", "head", "jump", "any" ],
    "threshold": 1.0 // runs from 0 to 1, default 0
  }
}
```

Here, it becomes possible to indicate a number of other interactions, with `interactions`: an array of ways for a player to interact.

| interaction | detection                                            |
| ----------- | ---------------------------------------------------- |
| `click`     | user clicks on the item (mouse / keyboard (as now))  |
| `hand`      | camera mode detects a hand inside the element        |
| `foot`      | camera mode detects a foot inside the element        |
| `body`      | camera mode detects a whole body inside the element  |
| `head`      | camera mode detects a head inside the element        |
| `jump`      | camera mode detects a foot following a jump motion   |
| `any`       | camera mode detects any body part inside the element |

Default for `interactions`, if not specified: `[ "click" ]`

`threshold` indicates how much of the body part counts as 'inside', eg. `1.0` means the whole of the hand must be inside the element's boundary, whereas `0.0` means at least 1 pixel. Default for `threshold` is `1.0`.

#### Player monitor

Create a `PlayerMonitor` for each player that camera mode detects, which can trigger callbacks with `PlayerMonitorEvent` objects containing:

- element id
- interaction

It should only trigger callbacks for interactions specified in `clickIdToStageId` (for now). There will be other interaction types in future.

#### Jump

The `jump` interaction is a special case:

- the vertical motion is classified as upward/downward/neither using a threshold to determine if the foot is moving
- a sequence of events must be tracked so that a jump can be detected:
  1. inside the element, no vertical motion
  2. inside the element, upward vertical motion
  3. (may leave the element, for a short period of time)
  4. inside the element, downward vertical motion
  5. inside the element, no vertical motion
