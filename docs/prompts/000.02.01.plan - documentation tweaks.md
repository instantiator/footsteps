# Plan: HTML documentation site

- **Branch:** `000.02.00-documentation-tweaks` (from `main`)
- **Commits:** one early commit recording the prompt decisions and this plan, then one commit for the implementation
- **Orchestrator:** DeepSeek V4.1 Flash. Sub-agent tiers: none — single model.

## Context

`docs/` is a set of Markdown pages plus a TypeDoc-generated Markdown API reference in `docs/tsdoc/`. Nothing under `docs/` is published: GitHub Pages serves only the app (`dist/client`), and GitHub's file view shows the generated Markdown but not the HTML. The API reference therefore has no left/right/main layout, and the pages are not browsable as a site.

The outcome is one HTML site at `<site>/docs/` on GitHub Pages: the Markdown pages rendered by VitePress, and the API reference rendered by TypeDoc's HTML theme at `<site>/docs/tsdoc/`.

### Decisions taken

| Decision | Choice |
|-|-|
| Where the HTML docs are viewable | Publish all of `docs/` at `<site>/docs/` on GitHub Pages |
| Markdown rendering | VitePress, default theme (left sidebar, right page outline, local search) |
| Generator for the API reference | TypeDoc's built-in HTML theme; drop `typedoc-plugin-markdown` |
| API output directory | `docs/tsdoc/` (replaces the Markdown output) |
| When the docs build runs | Only in `build:gh-pages`, so `npm run build` and `check.sh` are unchanged |
| Branch and commits | `000.02.00-documentation-tweaks`; early decisions/plan commit, then one implementation commit |
| Repository rename | Remote set to `instantiator/footsteps`; local directory name unchanged |

### Constraints and reuse

- Non-negotiables from `dev-qual/agents-files/remote/AGENTS.md`: no unrequested abstractions, zero lint/typecheck warnings, no `any`.
- Reuse the existing generation entry points: `typedoc.json` and `npm run docs:api`; `scripts/pre-commit-fixups.sh` already regenerates and stages `docs/tsdoc/` when `src/`, `typedoc.json` or `package.json` is staged.
- Reuse the existing Pages plumbing: `build:gh-pages` and `finish-static-build.sh` handle `BASE_URL`; the deploy workflow and CI both build through `build:gh-pages`, so no workflow change is needed.
- `docs/tsdoc/` is already ignored by `.prettierignore`; TypeDoc HTML must stay ignored there.
- Internal links use relative Markdown paths and anchors, including URL-encoded spaces in `docs/prompts/` and in `docs/outstanding-issues.md`; VitePress must resolve them.
- Existing generated assets: `docs/prompts/illustrations/*.png` are referenced relatively and must be copied by the docs build.
