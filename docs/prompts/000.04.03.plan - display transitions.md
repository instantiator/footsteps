# Plan: animate the camera viewport and display changes

- **Branch:** `000.04.00-camera-mode`
- **Commits:** one commit at the end, covering the existing static camera-view work and this animation work
- **Orchestrator:** DeepSeek V4.1 Flash. Sub-agent tiers: none — the stages share the transition state and need one judgement call after another

## Context

The game view now fits the camera's aspect ratio, but the fit snaps. This work adds the requested
motion: a 2s ease-in-out reshape when camera mode turns on or off, then the next display fades in
over 1s. Ordinary display changes fade the old display out over 1s, swap, then fade the new display
in over 1s.

The tweaks that led here are listed in
[`000.04.02.feedback - tweaks to camera mode.md`](000.04.02.feedback%20-%20tweaks%20to%20camera%20mode.md).

### Decisions taken

| Decision              | Choice                                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| Ordinary display fade | Old display fades out for 1s, the display swaps, then the new display fades in for 1s                                      |
| Camera reshape        | Old display stays visible for the 2s reshape, fades out over the final 1s, then the new display fades in for 1s (3s total) |
| Shape motion          | CSS `aspect-ratio` keyframe animation, 2s `ease-in-out`, driven by custom properties for the start and target ratios       |
| Scene fade            | One scene wrapper around display layers and camera layers fades with `opacity`; the HUD stays outside it                   |
| Display identity      | `getDisplayKey` hashes the visible overview, stage and challenge display purposes                                          |
| Interactivity         | Clicks and camera interactions are disabled while a display transition is running                                          |
| Reduced motion        | `prefers-reduced-motion: reduce` makes every transition immediate                                                          |
| Camera availability   | If camera mode turns on before the video reports its aspect ratio, keep the old display and wait before reshaping          |
| Avoided               | Crossfading two DOM trees; it would duplicate element ids and complicate camera target matching                            |
| Branch and commits    | Stay on `000.04.00-camera-mode`; one commit at the end after the comprehensive gate                                        |

### Constraints and reuse

- Reuse `isDefined`, `GameLayersLayout`, the layer wrappers, `useMediaQuery` from `@uidotdev/usehooks`, and the existing camera mocks.
- Keep the display layers' z-order and the camera layers inside one scene; the HUD remains above it.
- No `any` casts. TSDoc every new exported symbol. Comments explain intent.
- The browser suite runs in Chromium. If a browser cannot interpolate `aspect-ratio`, the shape falls back to a snap; the fades still run.
- Tests default to reduced motion, so existing specs stay fast. Transition specs opt into motion and use fake timers.
- Do not include `src/assets/license-report.json` or the untracked keep-awake prompt in the commit.

### Stage 1: Display identity and ordinary scene fades (single model)

**Brief:** Add `getDisplayKey` to `src/components/core/logic/RenderDataUtils.ts` and pass it from `Game` to `GameLayersLayout` as a new `displayKey` prop. In `GameLayersLayout.tsx`, wrap the display layers and camera layers in a positioned `.gameScene` element and add a transition hook that holds the previous layers while the scene fades out over 1s, swaps to the new layers, then fades in over 1s. Same-display content updates must pass straight through. Disable clicks, keyboard activation and camera interactions while a transition runs. Use `useMediaQuery("(prefers-reduced-motion: reduce)")` to skip the waits. Add a test `matchMedia` default and a helper to opt into motion.

**Tests:**

- `tests/RenderDataUtils.test.ts`: the key is stable while the same displays stay on screen; it changes for title → stages, overview → stage, challenge display purpose and challenge chunk changes.
- `tests/GameLayersLayout.test.tsx`: old display remains during the 1s fade-out; the new display appears and fades in after 1s; the transition ends after 2s; reduced motion swaps immediately; clicks and camera interactions do nothing while transitioning.
- Existing `Game.test.tsx` and layout tests still pass with reduced motion.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run tests/RenderDataUtils.test.ts tests/GameLayersLayout.test.tsx tests/Game.test.tsx`. Expected: all pass.

### Stage 2: Camera reshape animation (single model)

**Brief:** Extend the transition hook so a change in camera mode waits for the camera's aspect ratio when turning on, then measures the current viewport and the container. Set the start and target ratios as CSS custom properties and enable a 2s `aspect-ratio` keyframe animation. Hold the old display during the reshape, fade the scene out over the final 1s, swap the display and clear the animation class at 2s, then fade in over 1s. When only the camera setting changes, reshape without fading the scene. Add `.gameScene` and `.gameViewportReshaping` rules to `GameLayersLayout.css`, with reduced-motion overrides. Keep camera interactions disabled throughout.

**Tests:**

- `tests/GameLayersLayout.test.tsx`: camera on reshapes from the container ratio to the camera ratio, holds the old display, fades out at 1s, swaps at 2s and fades in by 3s; camera off does the reverse; no aspect ratio keeps the old display and waits; a camera-only change does not fade; reduced motion skips the waits.
- `tests/browser/viewport.spec.ts`: sample the viewport mid-transition, prove it ends at the camera ratio, prove the new overview is visible after the fade, and keep the existing all-stones-within-bounds assertion.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run tests/GameLayersLayout.test.tsx` + `npx playwright test tests/browser/viewport.spec.ts --workers=1`. Expected: all pass.
