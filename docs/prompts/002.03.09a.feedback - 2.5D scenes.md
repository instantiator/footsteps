In 2.5D mode, scenes don't seem to fill the screen. Prepare a plan that supports any width of monitor and can fill unused space.

The below are suggestions to help resolve this - please challenge any part of this prompt to find the best, most consistent, and most intuitive solution for developers / creators.

Figuring out what to show in the unused area of the screen is hard (ie. the borders), perhaps.

- Assumption: the scene itself is square if there's no camera
- Assumption: the scene matches the camera dimensions if there is one
- The floor and horizon backgrounds may be of a dimension that extends beyond the scene itself

Here's an ideal to aim for:

![scene and screen fill](./illustrations/002.03.09a%20-%20scene%20design%20and%20screen%20fill.png)

The graphic illustrates a scene with fixed wall heights. There are other options - ie. we'd like to support "fill vertically", "fill horizontally" (for some elements), and to be able to set the wall element's height based on what's inside it.

> Wall properties and wall background properties:
>
> - Distance from edge of floor (as now)
> - By default: height of the wall element is determined by what it contains
> - Optional property sets wall element height, either:
>   - element clips at that point, or
>   - might be expected to use background-image, and background-repeat
> - Optional boolean property to allow the wall element fill all visible vertical space, so:
>   - might be expected to use background-image, and background-repeat
>
> Rear wall and rear wall background properties:
>
> - All wall / wall background properties
> - Optional boolean property to allow the wall element fill all visible horizontal space, too
>
> Horizon background properties:
>
> - Distance from floor to horizon
> - Horizon is a special case of a rear wall / rear wall background
>   - It sets the far point for the floor background
>   - It always takes up all vertical and horizontal space
>
> Floor background properties:
>
> - Depth below floor (can be 0)
> - Fills all horizontal space
> - Fills from far point (a default if the horizon is not set) to the front of the visible area

NB. If a wall is set to fill all visible vertical space, this implies some kind of projection onto the screen, so that it's clear what height the cut-off is.

Challenge if necessary: I understand this to mean that the front of the wall determines the cut-off point. Perhaps we should allow the user to specify whether the nearer- or further- edge defines the wall height.

Wall backgrounds should also be able to fill all vertical space with similar rules.

Perhaps for cases where there's no floor/horizon background specified, we can permit a screen background to be specified too (or is that already covered by declaring a background another way?) - so allowing the creator to define _something_ other than the default white to fill in any unfilled space.
