Follow all related guidance from dev-qual.

## Game landing page

- Add a game landing page
- Its background is the game tile background
- It shows the game title and description in a semi-transparent box, as with the game tile
- Use the game's font

- It has a 'New game' button, bottom right, that then proceeds to the game
  - The 'New game' button is only enabled if all required permissions are granted

## Permissions

If camera mode is enabled for any part of the app, use of the camera will require the user to grant that permission. Do this up-front, ie. check for the permission when a game first loads.

Adjust the game landing page.

- Below the game title and description, add another semi-transparent box
  - It lists the required permissions for the game (or "No permissions needed.")
  - Each permission has a check mark if granted
  - Each permission has a button to initiate the request (perhaps labelled 'grant') if not granted

Each permission should be checked through the browser when this screen loads.

- Granting the camera permission initiates a request for that permission through the browser.
- After the request completes, the permission can be checked again.

## Keep-awake

Use the most widely supported mechanism to ensure that the device/screen stays on for the duration of a game - ie. while a game is open and active in a visible browser tab, and not in completed state, the browser ought not to permit its host device to sleep if at all possible.

## Game state storage

Store the game state using the most appropriate browser storage API, for each change to it.

Further adjust the game landing page:

- 'New game' button - always appears, erases and pre-existing stored game state stored, starts the game with a fresh game state
- 'Continue' button - only if there's current game state in storage: starts the game with this stored state
