# Application audit

Several of the more recent plans in `docs/prompts` (000.02 – 000.05) were implemented by DeepSeek. The features are fine; audit the code base for risks.

## Request

- Audit the code base for potential bugs: from these plans, and more generally
- Identify any other risks (`npm audit` reports 0 — is that the whole picture?)
- Prepare a list of issues, and plan any remediations

## Follow-up decisions on the plan

- Permission guard: anything other than `granted` bounces back to the landing page
- Wake lock: it should stay held; re-acquire it when the system releases it
- Battery: show a visible warning on every page when the battery is low
- Validator: check that `clickIdToStageId` names real stages
- Root error boundary: fine to leave for now, while still in development
- Tooling: pin every tool for local development, CI and deployment, with a single source of truth for versions
- Remove unused dependencies
