## Context

Two problems prompt this work:

- The `/setup` planner assumes a generic 4:3 webcam, but the user's camera is a 16:9 LifeCam HD-3000.
- The game opens the camera at 1280×720 (`AppConfig.cameraWidth/Height`, used by `CharacterCamera.tsx:45`), but the
  landing preview and calibration (`useCameraPicker.ts:70`) open it at the browser's default size, often 640×480. If
  that size is a crop, the calibrated corners don't line up in play.

The work in five parts:

- keep webcam specs in the code and generate `docs/webcams.md` from them;
- default `/setup` to the user's room and camera, with a camera picker;
- let players choose a camera configuration (a size), opened the same way everywhere;
- key each calibration by camera and configuration;
- re-lay out the landing page to the mock-up.

### Decisions (user)

| Decision         | Choice                                                                                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Config options   | Match the camera's label against the catalogue (e.g. `LifeCam HD-3000`, `FaceTime HD`). For an unknown camera, offer the presets 1280×720 and 640×480 where `track.getCapabilities()` allows them; if it isn't supported, offer both. |
| Old calibrations | Dropped. They were taken at an unknown size, so the player calibrates once more.                                                                                                                                                      |
| MacBook FOV      | The user measures it with `/setup`'s measured check and I fill in the diagonal it implies. Until then the row reads "not published", and picking it on `/setup` leaves the FOV unchanged.                                             |
| `webcams.md`     | Regenerated in the pre-commit fixups when the data or the generator is staged, like the licence report. A unit test fails if the doc and the data disagree.                                                                           |

### Decisions (mine, flag if wrong)

- **Calibration key:** `${deviceId ?? "default"}@${width}x${height}` from the _requested_ configuration. The preview,
  the calibration and the game all ask for the same size, so they get the same picture. The key is known before the
  stream opens, so `calibrationNeeded` can still run up front. A new storage key, `footsteps:floor-calibrations`,
  replaces `footsteps:floor-calibration`, and the old key is removed on first load.
- **Data as TypeScript** (changed in stage 1): Node 26 runs TypeScript directly, as `scripts/validate-resources.ts`
  already relies on, so the data is a typed module, `src/components/camera/Webcams.ts`, and the generator is
  `scripts/webcams-doc.ts`. It formats the doc with prettier's API, so the test and the hook produce the same text. No
  JSON file is needed.
- **New game:** confirms with the native `window.confirm` when there's a saved game.
- **"Play without the camera":** moves from its checkbox into the camera dropdown, as an option shown only for games
  where the camera is optional.

### Stage 3: Camera configurations and calibration

- **Choice:** `CameraChoice` (`src/components/camera/CameraChoice.ts`) gains `size?: { width; height }`.
- **Options:** a `cameraConfigs(label, track)` helper, beside `Webcams.ts`, returns the catalogue rows or the filtered
  presets.
- **Opening the camera:**
  - `useCameraPicker` opens the stream with `getCameraStream(choice.size ?? DEFAULT_SIZE, deviceId)`, and exposes the
    configuration options for the current device.
  - `DEFAULT_SIZE` is AppConfig's 1280×720.
  - `CharacterCamera.tsx` uses `loadCameraChoice().size`, falling back to AppConfig.
  - When the camera changes, the size resets to its first option.
- **Calibration** (`FloorCalibration.ts`):
  - `cameraKeyOf` includes the size;
  - the new storage key; the old one removed;
  - `forgetCalibration(key)` added;
  - the `ponytail:` comment updated.
- **Callers:** `GameLayersLayout.tsx:514`, `CalibrationView.tsx`, `CameraPicker.tsx` and `GamePermissionUtils.ts:59`
  all go through `cameraKeyOf(choice)`, so they follow the key change automatically.
- **Tests:**
  - `FloorCalibration.test.ts`: two sizes of one camera keep separate calibrations; the old key is removed;
    `forgetCalibration` forgets one key only.
  - `CameraPicker.test.tsx` and `CameraSupport.test.ts`: the requested size reaches `getUserMedia`; the configuration
    select appears only when there's more than one option; a catalogue label gives its rows; an unknown camera gives the
    presets filtered by capabilities.

- **Gate:** `check.sh --fast`; those tests; `tests/browser/camera.spec.ts` and `tests/browser/floor.spec.ts`.
