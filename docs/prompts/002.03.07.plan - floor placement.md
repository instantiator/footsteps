## Context

002.03.04 added calibration, the 2.5D scene mode and `FloorGeometry.ts`. Every room's floor is different, so authors can't hand-place items on it. This prompt gives items floor coordinates (`data-floor-*`), and the engine places, scales and depth-sorts them. Players get floor positions too: the engine uses them each frame, and rules and templates get them as quantised, rate-limited variables. `data-depth` goes away. Nanny's Magic Trifle and the rules demo become 2.5D games.

### Decisions taken

| Decision              | Choice                                                                                                                                                                                                                                                                                                                                                                                    |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Position variables    | `game.players.<number>.x` / `.y`, next to the existing `active`/`removed`/`frozen` counts, keyed by player number (as `event.player` and `.player-N` are). Numeric path steps work in filtrex (`dottedProp`) and Handlebars, both checked. A player with no position has no entry. The count stays `game.players.active`.                                                                 |
| Screen floor x        | Floor x 0 is the **screen's** left edge. When the camera is mirrored, the homography's x flips (`100 − x`). One helper in `FloorGeometry.ts` does this, so items and players agree.                                                                                                                                                                                                       |
| Ground point          | `y` as `groundOf` gives it now (the silhouette's bottom). `x` is the mean x of the mask pixels in the bottom band (the ground row up to 3% of the frame height above it). This needs no foot keypoints, which models often miss from behind.                                                                                                                                              |
| Jumps and smoothing   | `PositionFollower` generalises `DepthFollower`. `y` keeps today's window of the lowest ground plus the deadband. `x` follows the newest sample while that sample is within the deadband of the held `y`, and stays put otherwise, so it holds from take-off. It works in image %, and maps to floor or scene coordinates afterwards. The deadband keeps its meaning.                      |
| Anchor                | The engine sets the item's `transform-origin` to `data-floor-anchor`, and reads the browser's computed origin in px, so it never parses CSS itself. `scale` then keeps the anchor fixed, and `translate` = floor point − the anchor's layout position. The side effect is that `transform` animations (`floatAndZoom`) on a floor-placed item pivot on its anchor. This goes in the docs. |
| Layout position       | Summing `offsetLeft`/`offsetTop` up to `#game-viewport` gives the layout position, which ignores transforms and animations. `ponytail:` an ancestor with its own transform throws this off. Fix it by measuring through `getBoxQuads` or a probe if a game needs that.                                                                                                                    |
| When placement runs   | A `requestAnimationFrame` loop while the scene is 2.5D. It reads everything first, then writes only the values that changed, and it handles reshapes and template re-renders (idiomorph rewrites `style`). `ponytail:` it costs O(items) a frame; switch to Resize/Mutation observers if profiling shows a cost.                                                                          |
| Effects and placement | Item effects default to `composite: "add"` (`ItemEffects.ts:106`), so they add to the placement's inline `translate`/`scale`. `replace` effects (`ItemEffects.ts:54`) override it while they run, which is acceptable and gets documented.                                                                                                                                                |
| Thickness             | It applies to camera players only, as the prompt says. Mouse-feet points _at_ the item, and its floor y isn't where a body would stand.                                                                                                                                                                                                                                                   |
| 2D scenes             | Players aren't sorted (they stay at `UNSORTED_PLAYER_Z_INDEX`). Their position is the ground point as % of the scene, flipped when mirrored. `data-floor-*` does nothing.                                                                                                                                                                                                                 |
| `data-depth`          | `validate-game.sh` fails on it, naming `data-floor-y`. At runtime the placement loop logs it once per element with the same message and ignores it.                                                                                                                                                                                                                                       |
| `data-floor-*` in 2D  | A validator warning when the template's scene can never show in 2.5D (rule below). Warnings don't fail validation.                                                                                                                                                                                                                                                                        |
| Demo id               | It keeps the id `rules-demo`, so saved progress and tests survive. Only the title becomes "Demo scenes (2.5D)".                                                                                                                                                                                                                                                                           |

### Stage 1: Floor ↔ viewport geometry and placement maths

**Brief:** add pure functions to `src/components/camera/FloorGeometry.ts`, each with TSDoc. Update the module's header so it defines **screen floor coordinates** (x from the screen's left).

- `screenFloorForImage(corners, image, mirrored): Point` and `imageForScreenFloor(corners, floor, mirrored): Point`. These are the homography plus the mirror flip on x.
- `viewportPointForImage(image, placement: CropPlacement, mirrored): Point` and its inverse, `imagePointForViewport`, in viewport fractions. A mirrored image puts image x at `left + (1 − x) × width`, matching `cropPlacement`.
- `floorToViewport` / `viewportToFloor` compose the two above.
- `floorWidthRatio(corners, placement, mirrored, viewportSize, y)`: the on-screen pixel length of the floor row at `y`, over the front row's (`y = 100`).
- `placeOnFloor({ anchorLayout, floor, height, ratio })` returns `{ translate: Point, scale: number }` in px. The target is `floorToViewport(floor)` in px, moved up by `height × frontWidthPx × ratio / 100`. `translate` is that target minus `anchorLayout`, and `scale` is `ratio`.

**Tests** (`tests/FloorGeometry.test.ts`):

- A floor → viewport → floor round trip, mirrored and not.
- With the default corners, the floor's corners land on the expected viewport points, and the front corners on the bottom edge.
- Mirroring swaps the left and right edges on screen.
- The ratio is 1 at the front and below 1 at the back, matching the default corners' row widths (≈ 50/84 ≈ 0.6 at y = 0).
- `placeOnFloor` gives the translate for a known anchor. A height raises it in proportion to the ratio.

**Gate:** `dev-qual/scripts/check.sh --fast` and `npx vitest run tests/FloorGeometry.test.ts`.

### Stage 3: Placing floor items, and sorting them among players

- `parseFloorItem(element)` reads `data-floor-y` (required, any finite number), `-x`, `-height` (default 0), `-anchor` (default `center bottom`) and `-thickness`. It returns null when `data-floor-y` is missing or not a number. Values are content, so it doesn't clamp beyond finiteness, and it doesn't throw.

With no `floor`, it removes the properties it set. It also finds `[data-depth]` elements and `console.error`s once per element: `data-depth is no longer supported; use data-floor-y` (a `WeakSet` remembers which).

### Stage 5: Position variables

**Brief:**

- `src/components/camera/PositionPublisher.ts`, which is pure. Its constructor takes `{ cell, ratePerSecond }`. `update(positions: Map<number, Point>, now): Record<number, Point> | undefined` is keyed by player number, and returns the snapshot to publish, or undefined.
  - **Quantise:** a player's value is their cell's centre, or its lower edge. Pick one, document it, and test it.
  - **Hysteresis:** a player moves to a new cell only once they are `cell / 4` past the current cell's edge.
  - **Batch:** it returns every player's value together, including the removal of players who have gone.

## Notes for 002.03.14: ignoring spectators

- A spectator is a person whose ground point maps outside the floor (`screenFloorForImage` x or y outside 0–100, with a margin such as 5 units for feet at the edge), held for a short time so that someone stepping over the edge isn't dropped at once.
- `PlayerPositions` already has every person's floor position each frame, so the filter goes between it and `PlayerRegistry`/interactions. Spectators get no number, no interactions, no position variables and no count. Drawing them is a choice: dimmed, or not at all.
- In 2D scenes there is no floor, so nobody is a spectator. The rule needs the scene mode and calibration that stage 2 passes to `CharacterCanvas`.
- Take care with the margin and the hold: a jump lifts the ground point, but positions already hold through jumps, so judge spectators on the held position.
- Tests: someone standing outside the floor is ignored, walking on makes them a player, and a jump at the front edge doesn't drop them.
