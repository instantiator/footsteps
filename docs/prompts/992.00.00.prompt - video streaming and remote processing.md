Prepare a plan to evaluate streaming and remote processing of video. The output of the plan's implementation should be a new report, under `docs/reports/`

At current time, the performance of the camera's video stream processing is limited by the local machine's capability. This is sufficient, and _ok_, but not great.

We don't want to _replace_ this capability, but we should explore the option of processing the video remotely on a cloud service that can offer more power - so resulting in a higher accuracy of body segmentation and, potentially, a higher frame rate.

At current time, the accuracy of the processing is also _ok_, but not great. The user has a reasonably accurate outline, but background bleeds through (particularly between limbs that are close together, or where there's a gap (eg. a player puts their hand on their hip, creating a gap between arm and torso)). Sometimes unrelated pixels are confused and included in player body segmentation. The player's outline seems to shift a little too much, or seems a little inaccurate in places.

Is this even a problem that can be improved on with more computing power, or are we better off exploring how to train better models? Perhaps there are better models that need more computing power to run, or perhaps higher resolution frames can be processed on higher powered hardware. Are there parts of processing that can be done remotely, and others that can be done locally to improve performance or accuracy further?

Don't implement anything, unless there are small, local, tests we can run to evaluate certain aspects.

Questions to explore:

- Would a remote service on a cloud service provider (eg. AWS), be able to accept streaming video, process that video in real time, and generate a second, processed, video stream that can be consumed by footsteps?
- Which technologies are appropriate for this?
  - Explore offerings from: AWS, Google, Azure and any other cloud service provider you can identify as potentially relevant.
  - Where it's necessary to run our own code, ie. if there's no cloud-native offering that does this out of the box, example the use of severless, containerised, and VM technologies offered by these providers
- What lag might we expect? (Assume that the internet connection available is of sufficiently high bandwidth to hold 2 or more concurrent video calls.) Would it be manageable?
- Are there a variety of options that would result in different levels of performance?
- Are there a variety of options that would result in different levels of accuracy?
- What cost might we expect for each option?

Explore non-cloud options:

- Could a second or third machine on the local network provide additional computing power?
- Would this option offer a significant improvement to performance or accuracy?
- How might this be orchestrated?

Generate a table showing:

- technology
- variant (eg. option selected)
- expected cost
- expected processing performance
- expected lag

Also answer these questions in a recommendations section:

- Are these avenues worth exploring?
- Which option would you recommend?
