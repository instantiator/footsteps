## Context

The reference docs (`game-data.md`, `camera-mode.md`, `special-effects.md`, `positions-sizes-units.md`) say what each piece of a scene does, but not how to put the pieces together. Game authors know HTML, CSS and JSON, but not Footsteps' code. This work adds:

- six tutorials, each built on a real game in the repository;
- a toolkit: copy-and-paste sample elements with screenshots, an illustrated units guide, and a scene renderer page in the app.

None of it should be able to drift silently from the code.

### Decisions taken

| Decision            | Choice                                                                                                                                                                                                                                                                                                                                                                                                                                              |

A `[git:<rev>:<path>]` title checks against `git show <rev>:<path>`, for the "before" quotes in the conversion tutorial. |

The existing floor-coordinates SVG (`docs/prompts/illustrations/002.03.06 - floor coordinates.svg`) is copied into `docs/tutorials/images/` for the 2.5D tutorial.                                                |
| Renderer validation | **Move the template checks into `src/`.** `scripts/resource-checks.ts` and the renderer page share them.                                                                                                                                                                                                                                                                                                                                            |
| Tutorial location   | `docs/tutorials/`, listed in `docs/index.md` and in a "Tutorials" sidebar group in `docs/.vitepress/config.ts`.                                                                                                                                                                                                                                                                                                                                     |

### Constraints and reuse

- Link, don't repeat: every attribute, class and rule links to its reference section (`game-data.md#floor-surfaces`, `camera-mode.md#player-positions`, `special-effects.md#…`), and the tutorials don't restate them.
- Each tutorial starts from an empty scene and adds one thing at a time. After each step it says what to look for on screen, including what `?debug=true` shows.
- `RawRepository` game source (`src/entities/GameSource.ts`) supplies an in-memory repository, as `tests/helpers/GameProviders.tsx` does. The renderer reuses it.
- Template checks: `templateProblems`, `misplacedSurfaceAttributes`, `floorOnlyWarnings`, `startTags`, `SURFACE_ATTRIBUTES` (`scripts/resource-checks.ts:158–214`). They are pure regex, plus `SURFACE_CLASSES`/`FLOOR_AREA_ATTRIBUTE` from `src/components/core/layout/FloorSurfaceClasses.ts`.
- The static build prerenders every known route (`react-router.config.ts:10`), so a new route goes there too.
- The docs site is VitePress (`docs/.vitepress/config.ts`), published at `<base>docs/`. The app's renderer is at `<base>scene-renderer`, so docs link to it as `../scene-renderer`.
- If writing a tutorial shows that its game lacks something, or has a bug, make a small fix to the game and say so in the stage's commit. Ask first if the fix touches engine code.
- The Magic Trifle "before" state is `6819d57^` (the commit that made it 2.5D is `6819d57`; the template was then renamed `.hbs` → `.html` in `1caa013`).

### Stage 3: Quote checker (Opus)

**Brief:** `tests/TutorialQuotes.test.ts` globs `docs/**/*.md` except `docs/prompts/**`. For each fenced block whose info string has a `[title]`:

- If the title is a repo path, it reads that file. If it is `git:<rev>:<path>`, it uses `execFileSync("git", ["show", …])`.
- It trims each line and drops blank ones. Gap lines (`…`, `<!-- … -->`, `// …`) split the block into chunks.
- It asserts that each chunk appears as a contiguous run of trimmed lines in the file, and that the chunks come in order.
- On failure, it names the doc, the block's line number and the first missing line.

Keep the matcher as a small exported function in the test file.

**Tests:** in the same file, cases for the matcher: an exact match passes; a gap between two chunks passes; chunks out of order fail; a changed line fails; leading indentation is ignored.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run tests/TutorialQuotes.test.ts`. It passes trivially, since no tutorials exist yet.

### Stage 4: Sample elements and screenshots (Opus writes the samples; Sonnet may re-run the capture)

**Brief:**

- `docs/tutorials/samples/*.html` is one file per sample. Each is a complete template body that pastes into the renderer:
  - `screen-background`, `horizon`, `floor-background`;
  - a wall at its content's height, at a set `data-floor-height`, and filling the screen (`data-fill-height`, `data-fill-width`);
  - a side background;
  - a floor area;
  - a floor item (with anchor, height and thickness);
  - a clickable element;
  - a standable element (a `foot-enter` target);
  - the units examples: a fence of a given height, a tiled floor using `--floor-unit`, and a sky filling a wide screen.
- Use only inline styles and data URIs or CSS gradients, so the samples need no resources.
- `tests/browser/sample-screenshots.spec.ts` is skipped unless `CAPTURE_SAMPLES=1`. For each sample it opens `/scene-renderer`, fills the textarea, waits for the scene to render, and screenshots the scene pane to `docs/tutorials/images/<sample>.png`. Use a fixed viewport of 1280×720, and a 1920×720 extra shot for the wide-sky sample.
- Copy `docs/prompts/illustrations/002.03.06 - floor coordinates.svg` to `docs/tutorials/images/floor-coordinates.svg`.

**Tests:** `tests/TemplateChecks.test.ts` gets one case: every file in `docs/tutorials/samples/` gives no problems and no warnings from `templateMessages(text, true)`.

**Gate:** `dev-qual/scripts/check.sh --fast` + `npx vitest run tests/TemplateChecks.test.ts` + `CAPTURE_SAMPLES=1 scripts/run-browser-tests.sh sample-screenshots`. Then look at every PNG: each shows its element as described.
