## Context

The calibration page (`/game/:id/calibrate`, `src/components/landing/CalibrationView.tsx`, through
`src/pages/LocalCalibrate.tsx`) is a dark column that scrolls, and its picture is capped at 65vh. On a laptop, the steps, the
picture and the buttons don't fit on one screen. The mock-up asks for the landing page's look:

- panels above a fixed button bar;
- the camera picture filling the space left over;
- a clear unsaved state.

Under most circumstances it should all fit a laptop screen without scrolling.

## Layout (from the mock-up)

```text
┌ Game title: Floor calibration ───────────────────────────────┐   title panel
├ 1. Drag each blue corner…  2. Walk to each corner…  [Plan space]┤   steps panel
├ Calibrating: <camera> · <configuration>*  ───────────────────┤   calibration panel: fills the rest,
│   [ camera picture + floor + corner handles ]                 │   scrolls only below its minimum size
├──────────────────────────────────────────────────────────────┤
│ [Close] [Reset]                              [Save and close] │   fixed bar
└──────────────────────────────────────────────────────────────┘
```

- **Title:** "**<game title>:** Floor calibration". `LocalCalibrate` gains the same `GameRepositoryProvider` and
  `GameDataProvider` wrapping as `LocalGameLanding.tsx`, so `useGameData()` gives the title, the tile background and
  the font, as on the landing page.
- **Steps:** "Drag each blue corner…" and "Walk to each corner…", with the current step highlighted as now. The old
  step 3 ("Press Save…") goes, because the bar says it. **Plan space** sits at the right of the panel and opens
  `/setup` for this camera in a new tab, through the same `planPath` the landing page uses. `planPath` moves from
  `GameLanding.tsx` to a small shared module so both pages can use it.
- **Calibrating panel:**
  - The heading is "Calibrating: <camera label> · <configuration>", where the configuration is the catalogue name
    (such as "HD (1280×720)") or `W×H`.
  - An asterisk follows the heading while the corners differ from what's saved. An uncalibrated configuration starts
    on the default corners, which counts as unsaved, so it shows the asterisk.
  - The picture uses the space left, keeps its shape, and has a minimum size; the panel scrolls only below that.
  - "Only one person should be in view" moves over the picture, styled like the landing page's warnings.
- **Bar:**
  - **Close** goes back to the landing page. If there are unsaved changes, it first asks with `window.confirm`.
  - **Reset** puts the corners back to the defaults, unsaved. This is today's "Reset to the default area".
  - **Save and close** saves, then goes back. It is disabled while more than one person is in view.
- **Clear all calibrations (user):**
  - It stays on the calibration page, renamed from "Forget all saved areas", at the left of the bar after Reset.
  - It is added to the landing page too, below Clear beside the preview.
  - Both ask with `window.confirm` first, then call `forgetAllCalibrations`. On the landing page, the readiness then
    re-reads, as Clear does. On the calibration page, the corners stay, but they become unsaved, so the asterisk
    shows.
- **Removed:**
  - The "Saved / Not saved yet / Changes not saved yet" status, which the asterisk replaces.
  - The "Back to the game" link, which Close replaces.

**Changed after review (user):** after reviewing the layout in a browser, the page is two columns rather than the
mock-up's stack: the title and steps on the left (about a third of the width), and the calibrating panel on the right,
above the bar. Plan space sits below the steps. On narrow screens the columns stack and scroll together.

## Shared components (DRY)

The landing and calibration pages have the same parts. Today each part is marked up inline in `GameLanding.tsx` and
`CameraPicker.tsx`; they move into small shared components, and both pages use them:

| Component (new, `src/components/landing/`) | What it is                                                                                                                              | Used by                                                                            |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| `ButtonBar.tsx`                            | The fixed bottom bar: `start` and `end` groups with the gap between them (today `ActionBar`'s markup, with `.game-landing-actions-gap`) | the landing page's ActionBar; the calibration page's bar                           |
| `PlanSpaceLink.tsx`                        | The **Plan space** link: `/setup` for a camera in a new tab, with `planPath` inside it (moved from `GameLanding.tsx`)                   | the landing bar; the calibration steps panel                                       |
| `PictureWarnings.tsx`                      | The ⚠️ list over a picture (today inline in `CameraPreview`)                                                                            | the landing preview; the calibration picture ("Only one person should be in view") |
| `ClearAllCalibrations.tsx`                 | A button that confirms, calls `forgetAllCalibrations`, then calls back                                                                  | the landing floor buttons; the calibration bar                                     |

- **Styles:** `.game-button`, the bar and the warnings move from `GameLanding.css` into `GamePanel.css`, the shared
  sheet, which both pages import. `.game-panel` is already there.
- **Not shared:** the Calibrate/Reset/Clear buttons beside the landing preview are landing-only. The calibration
  page's Reset changes unsaved corners rather than storage, so it is different behaviour.
