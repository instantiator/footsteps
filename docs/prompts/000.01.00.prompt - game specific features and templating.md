## Game-specific features

There are a number of features, implemented in 2025, that are specific to the "Nanny's Magic Trifle" game. These were implemented at application level, due to time constraints.

Here are a couple that I'm aware of:

1. the application font is universal, and it's the bubbly font because that was needed for Nanny's Magic Trifle

   - it would be better if a game could specify its own font
   - the application needn't style its non-game pages yet

2. `GameDisplayScrollComponent` is a special case of _an input dialog with multi-page support_ - but the **generic** dialog doesn't exist. We ought to develop a generic base component, and then adjust the scroll component to be a special case where the image and style information are provided by the application.

   - There's a caveat for this: at the moment, the scroll component relies on some metadata about its background image - ideally, it wouldn't need that to be provided (ie. it would figure out things like image aspect ratios for itself, or use clever CSS rules so the browser could take care of it)
     - It'd still need margin info - so that if the background image has transparent margins, text isn't laid out further out than it should be

Are there others? Please review the code base. Clues:

- uses a piece of media or resource provided by the application, rather than the game repository
- contains something else specific to Nanny's Magic Trifle

Don't worry about the camera mode work - changes are planned for that in prompt 000.02.00.

## Handlebars / Mustache

We are currently using Mustache as our templating engine.

Please switch to Handlebars so that we can use helpers and more complex templates with conditional blocks in future.

This may require selection of a different library. Follow dev-qual guidelines, and propose an appropriate library in the plan.
