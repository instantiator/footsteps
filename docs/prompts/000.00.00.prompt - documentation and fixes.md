## TS docs

There are quite a lot of components and interfaces that do not have dev-qual coding guideline compliant code comments yet: Audit the project, identify and create a list of these.

Each should have a jsdoc/tsdoc compliant comment describing its intent / purpose. NB. This is usuallt the same as what the code does, but if there's a bug the intent and actual implementation may disagree. If the code seems to do something unexpected / diverges from the _apparent_ intention, add the item to a list of potential bugs for review.

Once commented, use jsdoc or tsdoc to generate documentation for the entire project. Place in `docs/jsdoc/` or `docs/tsdoc/` (as appropriate), and link to it from `docs/index.md` and `README.md`

## Tests

The test suite should be extended. Audit all the components and functions, and identify missing tests.

Write each test carefully - and test the intent of the functions and components to ensure that they're doing what they should. Where a test would fail, ensure that the function or component it tests is on the list of potential bugs for review, set the test to be skipped, and add a comment to the test so it's clear this test is for a bug that we want to fix.
