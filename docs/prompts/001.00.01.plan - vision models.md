## Context

`CharacterCanvas.tsx` runs BodyPix/ResNet50 on tfjs. It has a low frame rate, low resolution, flickering part labels, confusion from the background, and poor multi-player support. The goal is a model-agnostic vision layer, selected and tuned through typed app config, with the existing model optimised and two new models behind it.

### Findings from exploration

- **Multi-player is broken by config.** `SEGMENTATION_CONFIG` (`CharacterCanvas.tsx:46`) never sets `multiSegmentation`, so BodyPix merges everyone into one segmentation (`segmenter.js:122`). As a result, `players` is always length ≤ 1.
- **The mask is coarse.** `outputStride: 32` is BodyPix's coarsest setting, and `quantBytes: 4` is the largest (slowest) weight format.
- **The camera resolution is the default.** `getCameraStream` asks for `{ video: true }`, which typically gives 640×480.
- **There are 3 GPU→CPU readbacks per frame.** `readPlayers` calls `toImageData` per person, and `drawMask` calls `toBinaryMask` and then `toColoredMask`. Each one stalls the pipeline.
- **Frames are processed twice.** The loop is driven by `requestAnimationFrame`, which runs at 60–120 Hz on ProMotion, while the camera delivers 30 fps. Duplicate video frames get segmented again.
- **The MediaPipe shim is load-bearing, not dead.** `src/shims/mediapipe-selfie-segmentation.ts` exists because `@tensorflow-models/body-segmentation`'s entry point imports `@mediapipe/selfie_segmentation`, which Rolldown can't bundle (`vite.config.ts` alias). It can only be removed once BodyPix is imported by a route that skips that import (stage 5).
- **Integer arithmetic is already mostly in place.** `PlayerMonitor` counts into `Uint32Array`s and the loops use integer indices. Little to gain there.
- **The M1 GPU is reachable through WebGL (Metal via ANGLE) and WebGPU.** The Neural Engine is not reachable from a browser: WebNN is a Chrome origin trial (146–147) and its ONNX path is Windows-only. No cheap USB accelerator helps either. Coral/Hailo need native runtimes that can't be reached from a browser, and they're slower than the M1 GPU. Remote inference: rejected, because the round-trip latency is above one frame and it adds cost.

### Web check (Oct 2026)

- `@mediapipe/tasks-vision` is now 1.x (1.1.1).
- Ultralytics YOLO26 (Sept 2025) has an official `@ultralytics/yolo` browser package on LiteRT.js/WebGPU, covering pose and segmentation. It is AGPL-3.0, so the licence needs checking.
- RTMPose/RTMO run in the browser via ONNX Runtime Web (rtmlib-ts).
- Sapiens does 28-class part segmentation, but it is too slow for a browser.
- BodyPix/body-segmentation are deprecated.
- No real-time successor to BodyPix for body-part segmentation was found.

## Agreed decisions

- **Optimisations:**
  - cheap BodyPix fixes;
  - a WebGPU backend option;
  - temporal smoothing, with cross-frame player identity;
  - inference in a Web Worker.
- **New models:** MediaPipe Pose Landmarker, and MoveNet MultiPose paired with MediaPipe's selfie segmenter, which supplies the silhouette MoveNet lacks. All other options go in the ADRs, including the ones that were dismissed.
- **Body-part segmentation is dropped.** Most models don't offer it, and you agreed to drop it. Every model produces, for each person, a **silhouette mask** (for the cut-out) and **key points** (hands, feet, head). The "body part" in a query is a region around a key point, clipped to that person's silhouette. Its radius scales with the person's size (shoulder width, or head height). This keeps the "proportion of the hand inside the box" semantics.
- **Config:** Vite `.env` files and a typed parser. `FeatureFlagsProvider` becomes `AppConfigProvider`, and query params override config.

## Design

### Config (`src/config/`)

- **Env files:** `.env` holds shared defaults; `.env.development`, `.env.test` and `.env.production` hold overrides. These are Vite's own mode names, used by `npm run dev`, vitest, and `npm run build`, so CI picks them up with no changes. All of them are committed, because none hold secrets. Check that `.gitignore` doesn't exclude them.
- **Keys** (all `VITE_`):
  - `DEBUG`;
  - `VISION_MODEL` (`bodypix | mediapipe | movenet`);
  - `VISION_BACKEND` (`webgl | webgpu`, tfjs only);
  - `VISION_WORKER` (bool);
  - `VISION_MAX_PEOPLE` (int);
  - `VISION_SMOOTHING` (bool);
  - `VISION_STABLE_FRAMES` (int);
  - `CAMERA_WIDTH`, `CAMERA_HEIGHT`;
  - `BODYPIX_ARCHITECTURE` (`ResNet50 | MobileNetV1`), `BODYPIX_OUTPUT_STRIDE` (`8 | 16 | 32`), `BODYPIX_QUANT_BYTES` (`1 | 2 | 4`), `BODYPIX_INTERNAL_RESOLUTION` (`low | medium | high | full`), `BODYPIX_THRESHOLD`;
  - `MEDIAPIPE_VARIANT` (`lite | full | heavy`).
- **Types and parsing:**
  - `AppConfig.ts` holds a flat, typed `AppConfig`, `DEFAULT_APP_CONFIG`, and `parseAppConfig(source: Record<string, string | undefined>, base)`.
  - Each key has a small parser (bool, int, one-of). An invalid value warns once and keeps the base value.
  - Query param names are the camelCase keys (`?debug=true&visionModel=mediapipe`), and they go through the same parser.
  - `src/vite-env.d.ts` declares `ImportMetaEnv`.
- **Provider:** `AppConfigProvider` and `useAppConfig` replace `FeatureFlags{Context,Provider,Hook}.tsx`. Props still override defaults, as tests do today. Callers to update: `Game.tsx:173`, the 3 pages, `tests/helpers/GameProviders.tsx`, and `tests/FeatureFlagsProvider.test.tsx` (to be renamed).

### Vision layer (`src/vision/`)

- **`BodyPart.ts`:** a `const` object plus a union type (the project uses `erasableSyntaxOnly`, so no TS `enum`): `HEAD`, `LEFT_HAND`, `RIGHT_HAND`, `LEFT_FOOT`, `RIGHT_FOOT`, each with a colour and description.
  - The prompt asked to start from a duplicate of BodyPix's 24 parts. Since part segmentation is dropped, the list shrinks to the parts the game actually uses; `BODY` (the whole silhouette) stays a query option.
  - `body-seg-parts.json` is deleted. BodyPix's raw part values stay internal to `BodyPixModel`, which uses them to find its key points.
- **`VisionTypes.ts`:**
  - `VisionFrame { width, height, timestamp, people: VisionPerson[] }`;
  - `VisionPerson { id, mask: Uint8Array /* 1 = this person, per pixel */, keyPoints: KeyPoints, scale: number /* part radius in px */ }`;
  - `KeyPoints { leftFoot, rightFoot, leftHand, rightHand, headTop, headBottom, headLeft, headRight }`. Each is a `Point | null` in mask pixels.

  These are plain data with transferable buffers, so a frame can cross the worker boundary.

- **`FootstepsVisionModelImplementation.ts`:** an abstract base class. The prompt says "Foosteps"; this assumes "Footsteps".
  - Abstract members: `load(config)`, `detect(source: TexImageSource, timestamp): Promise<VisionFrame>`, `dispose()`.
  - Concrete query methods: `bodyPartsAt(frame, point) → {personId, part}[]` and `bodyPartsIn(frame, rect) → {personId, part, proportion}[]`. They delegate to pure functions in `VisionQueries.ts`, so they work on frames from any source, including the worker proxy.
- **Shared helpers in `VisionQueries.ts`:**
  - `partRegion(person, part)`: the key point's disc of radius `scale`, clipped to the mask (`HEAD` is the head box), which both queries count over.
  - `splitMaskByNearestSkeleton(mask, skeletons)`: gives each pixel of a combined silhouette to the person whose key points are nearest. It serves MoveNet + selfie segmenter.
- **Implementations and wiring:**
  - `models/BodyPixModel.ts`, `models/MediaPipePoseModel.ts`, `models/MoveNetModel.ts`.
  - `createVisionModel(config)` is a switch on `visionModel`.
  - `VisionWorkerProxy` extends the base class and forwards to `vision.worker.ts`.
- **Consumers:**
  - `PlayerFrame` is replaced by `VisionPerson`.
  - `PlayerMonitor`'s coverage counting (`countParts` / `countPartsInside`) is replaced by `bodyPartsIn`, and `feet` comes from `keyPoints`. The `foot` (and the jump state machine's) "feet" position is the midpoint of the two feet.
  - `findFeet` is deleted, but `offScreenThreshold_percent` stays (applied to the foot key points).
  - `drawMask` becomes `drawPeople(video, frame, ctx, maskType)`:
    - `binary`: the silhouette cut-out, built in one loop over the masks and composited as it is today;
    - `colored`: also tints each person differently, and their part regions by part;
    - `extremities`: tints only the hand and foot regions.
